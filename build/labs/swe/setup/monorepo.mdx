Open SWE는 Turbo 빌드 오케스트레이션을 사용하는 Yarn 워크스페이스 모노레포로 구성되어 있으며, 여러 애플리케이션과 공유 코드를 효율적으로 관리할 수 있도록 설계되었습니다. 이러한 구조는 코드 재사용, 일관된 도구 사용, 그리고 효율적인 개발 워크플로우를 가능하게 합니다.

## 레포지토리 구조

모노레포는 두 개의 주요 디렉토리로 구성되어 있습니다:

### 애플리케이션 (`apps/`)

**`apps/open-swe`** - LangGraph 에이전트 애플리케이션

- TypeScript로 작성된 핵심 LangGraph 에이전트 구현을 포함합니다
- manager, planner, programmer 세 가지 특화된 그래프를 포함합니다
- GitHub 웹훅 통합 및 LLM 상호작용을 처리합니다

**`apps/web`** - Next.js 웹 인터페이스

- Next.js 프레임워크를 사용하는 React 프론트엔드입니다
- Tailwind CSS와 함께 Shadcn UI 컴포넌트(Radix UI)를 사용합니다
- LangGraph 에이전트와 상호작용하기 위한 사용자 인터페이스를 제공합니다
- 안전한 통신을 위한 인증 및 프록시 라우트를 포함합니다

**`apps/docs`** - Mintlify 문서

- Mintlify로 구축된 문서 사이트를 포함합니다
- 포괄적인 설정 및 사용 가이드를 제공합니다
- API 문서 및 개발 리소스를 포함합니다

### 패키지 (`packages/`)

**`packages/shared`** - 공통 유틸리티 패키지

- 공유 타입, 상수, 유틸리티를 위한 중앙 집중식 위치입니다
- 에이전트 및 웹 애플리케이션 모두에서 사용됩니다
- `@openswe/shared` 네임스페이스를 통해 모듈을 내보냅니다
- 암호화 유틸리티, GraphState 타입, Open SWE 특화 모듈을 포함합니다

<Note>
  shared 패키지는 다른 패키지에서 임포트하기 전에 먼저 빌드되어야 합니다. 에이전트와 웹 앱 모두에서 사용되는 코드는 중복을 피하기 위해 이곳에 배치되어야 합니다.
</Note>

## Turbo 오케스트레이션

모노레포는 효율적인 빌드 오케스트레이션과 작업 관리를 위해 [Turbo](https://turbo.build/)를 사용합니다:

### 작업 의존성

```json
{
  "build": {
    "dependsOn": ["^build"],
    "outputs": ["dist/**", ".next/**", "!.next/cache/**"]
  },
  "lint": {
    "dependsOn": ["^lint"]
  }
}
```

`^build` 의존성은 공유 패키지가 의존하는 패키지보다 먼저 빌드되도록 보장하여, 모노레포 전체에서 적절한 빌드 순서를 유지합니다.

### 사용 가능한 스크립트

레포지토리 루트에서 다음 명령어를 실행하세요:

- `yarn build` - 의존성 순서대로 모든 패키지 빌드
- `yarn lint` - 모든 패키지에서 린팅 실행
- `yarn format` - Prettier를 사용하여 코드 포맷팅

## 의존성 관리 모범 사례

<Steps>
  <Step title="특정 패키지에 의존성 설치">
    의존성은 항상 사용되는 특정 패키지에 설치하고, resolution을 추가하는 경우가 아니라면 루트 `package.json`에는 절대 설치하지 마세요.

    ```bash
    # 올바름 - 특정 패키지에 설치
    cd apps/web
    yarn add some-package

    # 잘못됨 - 루트에 설치하지 마세요
    yarn add some-package
    ```
  </Step>

  <Step title="공유 의존성에 resolution 사용">
    여러 패키지에서 동일한 의존성이 필요한 경우, 루트 `package.json`에 resolution을 추가하여 버전 일관성을 보장하세요.

    ```json
    {
      "resolutions": {
        "@langchain/langgraph-sdk": "^0.0.95",
        "@langchain/core": "^0.3.58"
      }
    }
    ```
  </Step>

  <Step title="변경 후 shared 패키지 빌드">
    `packages/shared`를 수정한 경우 루트에서 `yarn build`를 실행하여 다른 패키지에서 사용할 수 있도록 하세요.

    ```bash
    # packages/shared 수정 후
    yarn build
    ```
  </Step>
</Steps>

## Postinstall 훅 요구사항

`apps/open-swe` 패키지는 중요한 `postinstall` 훅을 포함합니다:

```json
{
  "scripts": {
    "postinstall": "turbo build"
  }
}
```

<Note>
  이 postinstall 훅은 LangSmith 배포에 **필수**입니다. Open SWE는 모노레포이고 에이전트는 shared 패키지의 빌드된 파일에 접근해야 하므로, LangGraph 서버를 시작하기 전에 빌드 프로세스를 실행해야 합니다.
</Note>

### 왜 중요한가

1. **배포 호환성**: LangSmith는 모든 의존성이 빌드되고 사용 가능한 상태여야 합니다
2. **Shared 패키지 접근**: 에이전트는 컴파일되어야 하는 `@openswe/shared`의 유틸리티를 임포트합니다
3. **빌드 순서**: 에이전트가 사용을 시도하기 전에 shared 패키지가 빌드되도록 보장합니다

<Tip>
  개발 중 shared 패키지와 관련된 임포트 오류가 발생하면, 루트에서 `yarn build`를 실행하여 모든 패키지가 올바르게 빌드되고 링크되었는지 확인하세요.
</Tip>

## 워크스페이스 구성

모노레포는 다음 구성으로 Yarn 3.5.1을 사용합니다:

- **Node Linker**: 호환성을 위한 `node-modules`
- **Workspaces**: `apps/*` 및 `packages/*`에서 패키지를 자동으로 검색합니다
- **Package Manager**: `package.json`의 `packageManager` 필드를 통해 강제됩니다
