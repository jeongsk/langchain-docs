이 가이드는 로컬 개발을 위한 Open SWE 설정 과정을 안내합니다. 리포지토리 클론, 의존성 설치, 환경 변수 구성, GitHub App 생성, 개발 서버 시작 과정을 진행하게 됩니다.

<Note>
  이 설정은 개발 목적을 위한 것입니다. 프로덕션 배포를 위해서는
  URL을 조정하고 프로덕션용 별도의 GitHub App을 생성해야 합니다.
</Note>

## 사전 요구사항

시작하기 전에 다음 항목이 설치되어 있는지 확인하세요:

- Node.js (버전 18 이상)
- Yarn (버전 3.5.1 이상)
- Git

## 설정 단계

<Steps>
  <Step title="리포지토리 클론">
    Open SWE 리포지토리를 로컬 머신에 클론하세요:

    ```bash
    git clone https://github.com/langchain-ai/open-swe.git
    ```
    ```bash
    cd open-swe
    ```

  </Step>

  <Step title="의존성 설치">
    리포지토리 루트에서 Yarn을 사용하여 모든 의존성을 설치하세요:

    ```bash
    yarn install
    ```

    이 명령은 모노레포 워크스페이스의 모든 패키지에 대한 의존성을 설치합니다.

  </Step>

  <Step title="환경 파일 설정">
    환경 예제 파일을 복사하고 구성하세요:

    ```bash
    # 웹 앱 환경 파일 복사
    cp apps/web/.env.example apps/web/.env
    ```
    ```bash
    # 에이전트 환경 파일 복사
    cp apps/open-swe/.env.example apps/open-swe/.env
    ```

    ### 웹 앱 환경 변수 (`apps/web/.env`)

    다음 변수를 입력하세요 (GitHub App 값은 다음 단계에서 추가됩니다):

    ```bash Environment Variables [expandable]
    # 개발용 API URL
    NEXT_PUBLIC_API_URL="http://localhost:3000/api"
    LANGGRAPH_API_URL="http://localhost:2024"

    # 시크릿 암호화 키 (생성 명령어: openssl rand -hex 32)
    SECRETS_ENCRYPTION_KEY=""

    # GitHub App OAuth 설정 (GitHub App 생성 후 입력)
    NEXT_PUBLIC_GITHUB_APP_CLIENT_ID=""
    GITHUB_APP_CLIENT_SECRET=""
    GITHUB_APP_REDIRECT_URI="http://localhost:3000/api/auth/github/callback"

    # GitHub App 세부정보 (GitHub App 생성 후 입력)
    GITHUB_APP_NAME="open-swe-dev" # GitHub 앱 이름과 일치해야 하며, 공백은 제외합니다
    GITHUB_APP_ID=""
    GITHUB_APP_PRIVATE_KEY="-----BEGIN RSA PRIVATE KEY-----
    ...여기에 개인 키를 추가하세요...
    -----END RSA PRIVATE KEY-----
    "

    # API 키 제공 없이 Open SWE를 사용할 수 있는 GitHub 사용자명 목록
    # 이는 프로덕션에서만 사용됩니다. 개발 환경에서는 모든 사용자가 "허용된 사용자"입니다.
    # 유효한 JSON 문자열 배열이어야 합니다.
    NEXT_PUBLIC_ALLOWED_USERS_LIST='["your-github-username", "teammate-username"]'
    ```

    ### 에이전트 환경 변수 (`apps/open-swe/.env`)

    에이전트 환경 변수를 구성하세요:

    ```bash Environment Variables [expandable]
    # LangSmith 추적 및 배포
    LANGCHAIN_PROJECT="default"
    LANGCHAIN_API_KEY="lsv2_pt_..."  # LangSmith에서 가져오기
    LANGCHAIN_TRACING_V2="true"
    LANGCHAIN_TEST_TRACKING="false"

    # LLM 제공자 키 (최소 하나 필요)
    ANTHROPIC_API_KEY=""  # 권장 - 기본 제공자
    OPENAI_API_KEY=""     # 선택 사항
    GOOGLE_API_KEY=""     # 선택 사항

    # 인프라
    DAYTONA_API_KEY=""    # 필수. 클라우드 샌드박스용

    # 도구
    FIRECRAWL_API_KEY=""  # URL 콘텐츠 추출용

    # GitHub App 설정 (웹 앱과 동일)
    GITHUB_APP_NAME="open-swe-dev" # GitHub 앱 이름과 일치해야 하며, 공백은 제외합니다
    GITHUB_APP_ID=""
    GITHUB_APP_PRIVATE_KEY="-----BEGIN RSA PRIVATE KEY-----
    ...여기에 개인 키를 추가하세요...
    -----END RSA PRIVATE KEY-----
    "
    GITHUB_WEBHOOK_SECRET=""  # 다음 단계에서 생성

    # 서버 구성
    PORT="2024"
    OPEN_SWE_APP_URL="http://localhost:3000"
    SECRETS_ENCRYPTION_KEY=""  # 웹 앱 값과 일치해야 함

    # CI/CD. 자세한 내용은 /labs/swe/setup/ci를 참조하세요
    SKIP_CI_UNTIL_LAST_COMMIT="true"

    # API 키 제공 없이 Open SWE를 사용할 수 있는 GitHub 사용자명 목록
    # 이는 프로덕션에서만 사용됩니다. 개발 환경에서는 모든 사용자가 "허용된 사용자"입니다.
    # 유효한 JSON 문자열 배열이어야 합니다.
    NEXT_PUBLIC_ALLOWED_USERS_LIST='["your-github-username", "teammate-username"]'
    ```

    `NEXT_PUBLIC_ALLOWED_USERS_LIST` 환경 변수를 설정하지 않으면, 모든 사용자가 에이전트를 사용하기 위해 자신의 LLM API 키를 설정해야 합니다. 또한, `NEXT_PUBLIC_ALLOWED_USERS_LIST` 환경 변수(웹 및 에이전트 배포 모두)에 액세스를 허용하려는 GitHub 사용자의 사용자명을 포함하지 않으면, 웹훅 기능(GitHub 이슈에 레이블을 추가하여 새 실행 트리거, PR 리뷰에서 에이전트 태그 등)이 작동하지 않습니다.

    <Tip>
    `SECRETS_ENCRYPTION_KEY`는 `openssl rand -hex 32` 명령어로 생성하세요. 이 키는 두 환경 파일에서 동일해야 합니다.
    </Tip>

  </Step>

  <Step title="GitHub App 생성">
    <Note>
    **GitHub App**(GitHub OAuth App이 아님)을 생성해야 합니다. 이들은 서로 다른 기능을 가진 다른 유형의 애플리케이션입니다. 개발 환경과 프로덕션 환경을 위해 별도의 GitHub 앱 생성을 고려하세요.
    </Note>

    ### GitHub App 생성

    1. [GitHub App 생성 페이지](https://github.com/settings/apps/new)로 이동하세요
    2. 기본 정보를 입력하세요:
       - **GitHub App name**: 원하는 이름
       - **Description**: Open SWE 코딩 에이전트 개발 인스턴스
       - **Homepage URL**: 리포지토리 URL
       - **Callback URL**: `http://localhost:3000/api/auth/github/callback`

    ### OAuth 설정 구성

    - ✅ **Request user authorization (OAuth) during installation** - 사용자가 웹 앱에 로그인할 수 있도록 허용
    - ✅ **Redirect on update** - 권한 업데이트 후 사용자를 앱으로 리디렉션
    - ❌ **Expire user authorization tokens** - 토큰이 만료되지 않도록 유지

    ### 웹훅 설정

    1. ✅ **Enable webhook**
    2. **Webhook URL**: ngrok와 같은 도구를 사용하여 로컬 서버를 노출해야 합니다:
       ```bash
       # ngrok가 설치되어 있지 않다면 설치하세요
       # 그런 다음 로컬 LangGraph 서버를 노출하세요
       ngrok http 2024
       ```
       ngrok URL + `/webhooks/github`를 사용하세요 (예: `https://abc123.ngrok.io/webhooks/github`)

    3. **Webhook secret**: 이 값을 생성하고 저장하세요:
       ```bash
       openssl rand -hex 32
       ```
       이 값을 `apps/open-swe/.env`의 `GITHUB_WEBHOOK_SECRET`에 추가하세요

    ### 권한 구성

    **리포지토리 권한:**
    - **Contents**: 읽기 및 쓰기
    - **Issues**: 읽기 및 쓰기
    - **Pull requests**: 읽기 및 쓰기
    - **Metadata**: 읽기 전용 (자동으로 활성화됨)

    **조직 권한:** 없음

    **계정 권한:** 없음

    ### 이벤트 구독

    - ✅ **Issues** - 웹훅 기능에 필요
    - ✅ **Pull request review** - PR 태그 기능에 필요
    - ✅ **Pull request review comment** - PR 태그 기능에 필요
    - ✅ **Issue comment** - PR 태그 기능에 필요

    ### 설치 설정

    - **Where can this GitHub App be installed?**:
      - 더 넓은 테스트를 위해 "Any account" 선택
      - 또는 리포지토리로 제한하려면 "Only on this account" 선택

    ### 앱 생성 완료

    **Create GitHub App**을 클릭하여 설정을 완료하세요.

    ### 앱 자격 증명 수집

    앱을 생성한 후, 다음 값을 수집하여 두 환경 파일에 추가하세요:

    - **GITHUB_APP_NAME**: 선택한 이름
    - **GITHUB_APP_ID**: "About" 섹션에서 확인 (예: `12345678`)
    - **NEXT_PUBLIC_GITHUB_APP_CLIENT_ID**: "About" 섹션에서 확인
    - **GITHUB_APP_CLIENT_SECRET**:
      1. "Client secrets" 섹션으로 스크롤
      2. "Generate new client secret" 클릭
      3. 생성된 값 복사
    - **GITHUB_APP_PRIVATE_KEY**:
      1. "Private keys" 섹션으로 스크롤
      2. "Generate a private key" 클릭
      3. `.pem` 파일을 다운로드하고 내용 복사
      4. 줄 바꿈을 `\\n`으로 하여 한 줄로 포맷하거나, 예제에 표시된 여러 줄 형식을 사용하세요
    - **GITHUB_APP_REDIRECT_URI**: 로컬 개발의 경우 `http://localhost:3000/api/auth/github/callback`, 프로덕션의 경우 `https://your-production-url.com/api/auth/github/callback`이어야 합니다.
    - **GITHUB_WEBHOOK_SECRET**: 이 값을 생성하고 저장하세요:
      ```bash
      openssl rand -hex 32
      ```
      이 값을 `apps/open-swe/.env`와 `apps/web/.env`의 `GITHUB_WEBHOOK_SECRET`에 추가하세요.

    다음은 GitHub App 설정에서 환경 변수 값을 찾을 수 있는 위치를 보여주는 스크린샷입니다.

    <Accordion title="GitHub App OAuth 설정">

      - `GITHUB_APP_ID`
      - `NEXT_PUBLIC_GITHUB_APP_CLIENT_ID`
      - `GITHUB_APP_CLIENT_SECRET`
      - `GITHUB_APP_REDIRECT_URI`
      - `GITHUB_APP_PRIVATE_KEY`

    <Tip>
    GitHub App 자격 증명을 안전하게 보관하고 버전 관리에 커밋하지 마세요. `.env` 파일은 이미 `.gitignore`에 포함되어 있습니다.
    </Tip>

  </Step>

  <Step title="개발 서버 시작">
    모든 환경 변수가 구성되었으면, 두 개발 서버를 모두 시작하세요:

    **터미널 1 - LangGraph 에이전트 시작:**
    ```bash
    # apps/open-swe
    yarn dev
    ```
    이 명령은 `http://localhost:2024`에서 LangGraph 서버를 시작합니다

    **터미널 2 - 웹 애플리케이션 시작:**
    ```bash
    # apps/web
    yarn dev
    ```
    이 명령은 `http://localhost:3000`에서 Next.js 웹 앱을 시작합니다

    <Note>
    전체 기능을 위해서는 두 서버가 동시에 실행되어야 합니다. 웹 앱은 API 호출을 통해 LangGraph 에이전트와 통신합니다.
    </Note>

  </Step>
</Steps>

## 검증

두 서버가 모두 실행되면:

1. **웹 앱 방문**: `http://localhost:3000`으로 이동하세요
2. **GitHub 인증 테스트**: GitHub 계정으로 로그인을 시도하세요

<Tip>
  문제가 발생하면 두 터미널 창의 콘솔 로그에서
  오류 메시지를 확인하세요. 일반적인 문제로는 환경 변수 누락 또는
  잘못된 GitHub App 구성이 있습니다.
</Tip>
