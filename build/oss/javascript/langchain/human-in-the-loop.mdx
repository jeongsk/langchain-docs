title: Human-in-the-loop
---


Human-in-the-Loop(HITL) middleware를 사용하면 agent 도구 호출에 사람의 감독을 추가할 수 있습니다.
모델이 검토가 필요할 수 있는 작업(예: 파일 작성 또는 SQL 실행)을 제안할 때 middleware는 실행을 일시 중지하고 결정을 기다릴 수 있습니다.

이것은 구성 가능한 정책에 대해 각 도구 호출을 확인하여 수행됩니다. 개입이 필요한 경우 middleware는 실행을 중단하는 [interrupt](https://langchain-ai.github.io/langgraphjs/reference/functions/langgraph.interrupt-2.html)를 발생시킵니다. 그래프 state는 LangGraph의 [지속성 계층](/oss/javascript/langgraph/persistence)을 사용하여 저장되므로 실행을 안전하게 일시 중지하고 나중에 재개할 수 있습니다.

그런 다음 사람의 결정이 다음에 발생할 일을 결정합니다: 작업을 그대로 승인(`approve`)하거나, 실행 전에 수정(`edit`)하거나, 피드백과 함께 거부(`reject`)할 수 있습니다.

## Interrupt 결정 유형

Middleware는 사람이 interrupt에 응답할 수 있는 세 가지 내장 방법을 정의합니다:

| 결정 유형 | 설명                                                               | 사용 사례 예                                    |
|---------------|---------------------------------------------------------------------------|-----------------------------------------------------|
| ✅ `approve`   | 작업이 그대로 승인되고 변경 없이 실행됩니다.                | 작성된 대로 정확히 이메일 전송              |
| ✏️ `edit`     | 도구 호출이 수정과 함께 실행됩니다.                             | 이메일을 보내기 전에 수신자 변경        |
| ❌ `reject`    | 도구 호출이 거부되고 설명이 대화에 추가됩니다. | 이메일 초안을 거부하고 다시 작성하는 방법 설명 |

각 도구에 사용 가능한 결정 유형은 `interrupt_on`에서 구성하는 정책에 따라 다릅니다.
여러 도구 호출이 동시에 일시 중지되면 각 작업에는 별도의 결정이 필요합니다.
결정은 interrupt 요청에 나타나는 작업과 동일한 순서로 제공되어야 합니다.

<Tip>
도구 인수를 **편집**할 때는 신중하게 변경하세요. 원래 인수를 크게 수정하면 모델이 접근 방식을 재평가하여 도구를 여러 번 실행하거나 예상치 못한 작업을 수행할 수 있습니다.
</Tip>


## Interrupt 구성

HITL을 사용하려면 agent를 생성할 때 agent의 `middleware` 목록에 middleware를 추가하세요.

각 작업에 허용되는 결정 유형에 대한 도구 작업 매핑으로 구성합니다. Middleware는 도구 호출이 매핑의 작업과 일치할 때 실행을 중단합니다.



```ts
import { createAgent, humanInTheLoopMiddleware } from "langchain"; // [!code highlight]
import { MemorySaver } from "@langchain/langgraph"; // [!code highlight]

const agent = createAgent({
    model: "openai:gpt-4o",
    tools: [writeFileTool, executeSQLTool, readDataTool],
    middleware: [
        humanInTheLoopMiddleware({
            interruptOn: {
                write_file: true, // 모든 결정 (승인, 편집, 거부) 허용
                execute_sql: {
                    allowedDecisions: ["approve", "reject"],
                    // 편집 불가
                    description: "🚨 SQL execution requires DBA approval",
                },
                // 안전한 작업, 승인 불필요
                read_data: false,
            },
            // Interrupt 메시지의 접두사 - 도구 이름 및 인수와 결합하여 전체 메시지 생성
            // 예: "Tool execution pending approval: execute_sql with query='DELETE FROM...'"
            // 개별 도구는 interrupt 구성에서 "description"을 지정하여 이를 재정의할 수 있습니다
            descriptionPrefix: "Tool execution pending approval",
        }),
    ],
    // Human-in-the-loop은 interrupt를 처리하기 위해 체크포인팅이 필요합니다.
    // 프로덕션에서는 AsyncPostgresSaver와 같은 영구 checkpointer를 사용하세요.
    checkpointer: new MemorySaver(), // [!code highlight]
});
```



<Info>
    Interrupt 간에 그래프 state를 유지하려면 checkpointer를 구성해야 합니다.
    프로덕션에서는 @[`AsyncPostgresSaver`]와 같은 영구 checkpointer를 사용하세요. 테스트 또는 프로토타이핑의 경우 @[`InMemorySaver`]를 사용하세요.

    Agent를 호출할 때 대화 스레드와 실행을 연결하는 **스레드 ID**를 포함하는 `config`를 전달하세요.
    자세한 내용은 [LangGraph interrupt 문서](/oss/javascript/langgraph/interrupts)를 참조하세요.
</Info>


## Interrupt에 응답

Agent를 호출하면 완료되거나 interrupt가 발생할 때까지 실행됩니다. Interrupt는 도구 호출이 `interrupt_on`에서 구성한 정책과 일치할 때 트리거됩니다. 이 경우 호출 결과에는 검토가 필요한 작업과 함께 `__interrupt__` 필드가 포함됩니다. 그런 다음 해당 작업을 검토자에게 제시하고 결정이 제공되면 실행을 재개할 수 있습니다.




```typescript
import { HumanMessage } from "@langchain/core/messages";
import { Command } from "@langchain/langgraph";

// 대화 스레드와 실행을 연결하기 위해 스레드 ID를 제공해야 합니다.
// 이렇게 하면 대화를 일시 중지하고 재개할 수 있습니다 (사람의 검토에 필요함).
const config = { configurable: { thread_id: "some_id" } }; // [!code highlight]

// Interrupt가 발생할 때까지 그래프를 실행합니다.
const result = await agent.invoke(
    {
        messages: [new HumanMessage("Delete old records from the database")],
    },
    config // [!code highlight]
);


// Interrupt에는 action_requests 및 review_configs가 포함된 전체 HITL 요청이 포함됩니다
console.log(result.__interrupt__);
// > [
// >    Interrupt(
// >       value: {
// >          action_requests: [
// >             {
// >                name: 'execute_sql',
// >                arguments: { query: 'DELETE FROM records WHERE created_at < NOW() - INTERVAL \'30 days\';' },
// >                description: 'Tool execution pending approval\n\nTool: execute_sql\nArgs: {...}'
// >             }
// >          ],
// >          review_configs: [
// >             {
// >                action_name: 'execute_sql',
// >                allowed_decisions: ['approve', 'reject']
// >             }
// >          ]
// >       }
// >    )
// > ]

// 승인 결정으로 재개
await agent.invoke(
    new Command({ // [!code highlight]
        resume: { decisions: [{ type: "approve" }] }, // 또는 "edit", "reject" [!code highlight]
    }), // [!code highlight]
    config // 일시 중지된 대화를 재개하려면 동일한 스레드 ID
);
```


### 결정 유형

<Tabs>
<Tab title="✅ approve">
도구 호출을 그대로 승인하고 변경 없이 실행하려면 `approve`를 사용하세요.



```typescript
await agent.invoke(
    new Command({
        // 결정은 목록으로 제공되며, 검토 중인 작업당 하나입니다.
        // 결정의 순서는 `__interrupt__` 요청에 나열된 작업의 순서와 일치해야 합니다.
        resume: {
            decisions: [
                {
                    type: "approve",
                }
            ]
        }
    }),
    config  // 일시 중지된 대화를 재개하려면 동일한 스레드 ID
);
```

</Tab>
<Tab title="✏️ edit">
    실행 전에 도구 호출을 수정하려면 `edit`를 사용하세요.
    새 도구 이름과 인수로 편집된 작업을 제공하세요.



    ```typescript
    await agent.invoke(
        new Command({
            // 결정은 목록으로 제공되며, 검토 중인 작업당 하나입니다.
            // 결정의 순서는 `__interrupt__` 요청에 나열된 작업의 순서와 일치해야 합니다.
            resume: {
                decisions: [
                    {
                        type: "edit",
                        // 도구 이름과 인수가 포함된 편집된 작업
                        editedAction: {
                            // 호출할 도구 이름.
                            // 일반적으로 원래 작업과 동일합니다.
                            name: "new_tool_name",
                            // 도구에 전달할 인수.
                            args: { key1: "new_value", key2: "original_value" },
                        }
                    }
                ]
            }
        }),
        config  // 일시 중지된 대화를 재개하려면 동일한 스레드 ID
    );
    ```


    <Tip>
        도구 인수를 **편집**할 때는 신중하게 변경하세요. 원래 인수를 크게 수정하면 모델이 접근 방식을 재평가하여 도구를 여러 번 실행하거나 예상치 못한 작업을 수행할 수 있습니다.
    </Tip>

</Tab>

<Tab title="❌ reject">
    도구 호출을 거부하고 실행 대신 피드백을 제공하려면 `reject`를 사용하세요.



    ```typescript
    await agent.invoke(
        new Command({
            // 결정은 목록으로 제공되며, 검토 중인 작업당 하나입니다.
            // 결정의 순서는 `__interrupt__` 요청에 나열된 작업의 순서와 일치해야 합니다.
            resume: {
                decisions: [
                    {
                        type: "reject",
                        // 작업이 거부된 이유에 대한 설명
                        message: "No, this is wrong because ..., instead do this ...",
                    }
                ]
            }
        }),
        config  // 일시 중지된 대화를 재개하려면 동일한 스레드 ID
    );
    ```


`message`는 agent가 작업이 거부된 이유와 대신 무엇을 해야 하는지 이해하는 데 도움이 되도록 대화에 피드백으로 추가됩니다.

### 여러 결정

여러 작업이 검토 중일 때 interrupt에 나타나는 순서와 동일한 순서로 각 작업에 대한 결정을 제공하세요:



```typescript
{
    decisions: [
        { type: "approve" },
        {
            type: "edit",
            editedAction: {
                name: "tool_name",
                args: { param: "new_value" }
            }
        },
        {
            type: "reject",
            message: "This action is not allowed"
        }
    ]
}
```

## 실행 생명주기

Middleware는 모델이 응답을 생성한 후 도구 호출이 실행되기 전에 실행되는 `after_model` 훅을 정의합니다:

1. Agent가 모델을 호출하여 응답을 생성합니다.
2. Middleware가 응답에서 도구 호출을 검사합니다.
3. 호출 중 사람의 입력이 필요한 경우 middleware는 `action_requests` 및 `review_configs`가 포함된 `HITLRequest`를 구축하고 [interrupt](https://langchain-ai.github.io/langgraphjs/reference/functions/langgraph.interrupt-2.html)를 호출합니다.
4. Agent는 사람의 결정을 기다립니다.
5. `HITLResponse` 결정에 따라 middleware는 승인되거나 편집된 호출을 실행하고, 거부된 호출에 대한 @[ToolMessage]를 합성하고, 실행을 재개합니다.



## 사용자 정의 HITL 로직

더 전문화된 워크플로우의 경우 [interrupt](https://langchain-ai.github.io/langgraphjs/reference/functions/langgraph.interrupt-2.html) primitive와 [middleware](/oss/javascript/langchain/middleware) 추상화를 직접 사용하여 사용자 정의 HITL 로직을 구축할 수 있습니다.

Interrupt를 agent의 작업에 통합하는 방법을 이해하려면 위의 [실행 생명주기](#실행-생명주기)를 검토하세요.
