```python
from langchain.agents import create_agent
from langchain.agents.middleware import SummarizationMiddleware, HumanInTheLoopMiddleware

agent = create_agent(
    model="openai:gpt-4o",
    tools=[...],
    middleware=[SummarizationMiddleware(), HumanInTheLoopMiddleware()],
)
```




## 내장 middleware

LangChain은 일반적인 사용 사례를 위한 사전 구축된 middleware를 제공합니다:

### 요약(Summarization)

토큰 제한에 도달할 때 대화 기록을 자동으로 요약합니다.

<Tip>
**다음과 같은 경우에 적합합니다:**
- 컨텍스트 윈도우를 초과하는 장기 대화
- 광범위한 기록을 가진 다중 턴 대화
- 전체 대화 컨텍스트 보존이 중요한 애플리케이션
</Tip>

```python
from langchain.agents import create_agent
from langchain.agents.middleware import SummarizationMiddleware

agent = create_agent(
    model="openai:gpt-4o",
    tools=[weather_tool, calculator_tool],
    middleware=[
        SummarizationMiddleware(
            model="openai:gpt-4o-mini",
            max_tokens_before_summary=4000,  # 4000 토큰에서 요약 트리거
            messages_to_keep=20,  # 요약 후 마지막 20개 메시지 유지
            summary_prompt="Custom prompt for summarization...",  # 선택사항
        ),
    ],
)
```




<Accordion title="구성 옵션">

<ParamField body="model" type="string" required>
  요약을 생성하는 모델
</ParamField>

<ParamField body="max_tokens_before_summary" type="number">
  요약을 트리거하는 토큰 임계값
</ParamField>

<ParamField body="messages_to_keep" type="number" default="20">
  보존할 최근 메시지 수
</ParamField>

<ParamField body="token_counter" type="function">
  커스텀 토큰 계산 함수. 기본값은 문자 기반 계산입니다.
</ParamField>

<ParamField body="summary_prompt" type="string">
  커스텀 프롬프트 템플릿. 지정하지 않으면 내장 템플릿을 사용합니다.
</ParamField>

<ParamField body="summary_prefix" type="string" default="## Previous conversation summary:">
  요약 메시지의 접두사
</ParamField>




</Accordion>

### Human-in-the-loop

도구 호출이 실행되기 전에 사람의 승인, 편집 또는 거부를 위해 에이전트 실행을 일시 중지합니다.

<Tip>
**다음과 같은 경우에 적합합니다:**
- 사람의 승인이 필요한 고위험 작업 (데이터베이스 쓰기, 금융 거래)
- 사람의 감독이 필수인 규정 준수 워크플로
- 사람의 피드백이 에이전트를 안내하는 데 사용되는 장기 실행 대화
</Tip>

```python
from langchain.agents import create_agent
from langchain.agents.middleware import HumanInTheLoopMiddleware

agent = create_agent(
    model="openai:gpt-4o",
    tools=[read_email_tool, send_email_tool],
    middleware=[
        HumanInTheLoopMiddleware(
            interrupt_on={
                # 이메일 전송에 대해 승인, 편집 또는 거부 필요
                "send_email": {
                    "allowed_decisions": ["approve", "edit", "reject"],
                },
                # 이메일 읽기는 자동 승인
                "read_email": False,
            }
        ),
    ],
)
```




<Accordion title="구성 옵션">

<ParamField body="interrupt_on" type="dict" required>
  도구 이름과 승인 구성의 매핑. 값은 `True` (기본 구성으로 중단), `False` (자동 승인) 또는 `InterruptOnConfig` 객체일 수 있습니다.
</ParamField>

<ParamField body="description_prefix" type="string" default="Tool execution requires approval">
  액션 요청 설명의 접두사
</ParamField>

**`InterruptOnConfig` 옵션:**

<ParamField body="allowed_decisions" type="list[string]">
  허용된 결정 목록: `"approve"`, `"edit"` 또는 `"reject"`
</ParamField>

<ParamField body="description" type="string | callable">
  커스텀 설명을 위한 정적 문자열 또는 호출 가능한 함수
</ParamField>




</Accordion>

<Note>
**중요:** Human-in-the-loop middleware는 중단 간 상태를 유지하기 위해 [checkpointer](/oss/python/langgraph/persistence#checkpoints)가 필요합니다.

전체 예제와 통합 패턴은 [human-in-the-loop 문서](/oss/python/langchain/human-in-the-loop)를 참조하세요.
</Note>

### Anthropic 프롬프트 캐싱

Anthropic 모델에서 반복적인 프롬프트 접두사를 캐싱하여 비용을 절감합니다.

<Tip>
**다음과 같은 경우에 적합합니다:**
- 긴 반복 시스템 프롬프트를 가진 애플리케이션
- 여러 호출에서 동일한 컨텍스트를 재사용하는 에이전트
- 대량 배포의 API 비용 절감
</Tip>

<Info>
[Anthropic Prompt Caching](https://docs.claude.com/en/docs/build-with-claude/prompt-caching#cache-limitations) 전략 및 제한사항에 대해 자세히 알아보세요.
</Info>

```python
from langchain_anthropic import ChatAnthropic
from langchain.agents.middleware.prompt_caching import AnthropicPromptCachingMiddleware
from langchain.agents import create_agent

LONG_PROMPT = """
Please be a helpful assistant.

<Lots more context ...>
"""

agent = create_agent(
    model=ChatAnthropic(model="claude-sonnet-4-latest"),
    system_prompt=LONG_PROMPT,
    middleware=[AnthropicPromptCachingMiddleware(ttl="5m")],
)

# 캐시 저장
agent.invoke({"messages": [HumanMessage("Hi, my name is Bob")]})

# 캐시 히트, 시스템 프롬프트가 캐시됨
agent.invoke({"messages": [HumanMessage("What's my name?")]})
```




<Accordion title="구성 옵션">

<ParamField body="type" type="string" default="ephemeral">
  캐시 유형. 현재 `"ephemeral"`만 지원됩니다.
</ParamField>

<ParamField body="ttl" type="string" default="5m">
  캐시된 콘텐츠의 유지 시간. 유효한 값: `"5m"` 또는 `"1h"`
</ParamField>

<ParamField body="min_messages_to_cache" type="number" default="0">
  캐싱이 시작되기 전 최소 메시지 수
</ParamField>

<ParamField body="unsupported_model_behavior" type="string" default="warn">
  Anthropic이 아닌 모델을 사용할 때의 동작. 옵션: `"ignore"`, `"warn"` 또는 `"raise"`
</ParamField>




</Accordion>

### 모델 호출 제한

무한 루프나 과도한 비용을 방지하기 위해 모델 호출 수를 제한합니다.

<Tip>
**다음과 같은 경우에 적합합니다:**
- 폭주하는 에이전트가 너무 많은 API 호출을 하는 것을 방지
- 프로덕션 배포에서 비용 통제 적용
- 특정 호출 예산 내에서 에이전트 동작 테스트
</Tip>

```python
from langchain.agents import create_agent
from langchain.agents.middleware import ModelCallLimitMiddleware

agent = create_agent(
    model="openai:gpt-4o",
    tools=[...],
    middleware=[
        ModelCallLimitMiddleware(
            thread_limit=10,  # 스레드당 최대 10회 호출 (실행 간)
            run_limit=5,  # 실행당 최대 5회 호출 (단일 호출)
            exit_behavior="end",  # 또는 "error"로 예외 발생
        ),
    ],
)
```




<Accordion title="구성 옵션">

<ParamField body="thread_limit" type="number">
  스레드의 모든 실행에서 최대 모델 호출 수. 기본값은 제한 없음입니다.
</ParamField>

<ParamField body="run_limit" type="number">
  단일 호출당 최대 모델 호출 수. 기본값은 제한 없음입니다.
</ParamField>

<ParamField body="exit_behavior" type="string" default="end">
  제한에 도달했을 때의 동작. 옵션: `"end"` (정상 종료) 또는 `"error"` (예외 발생)
</ParamField>




</Accordion>

### 도구 호출 제한

특정 도구 또는 모든 도구에 대한 호출 수를 제한합니다.

<Tip>
**다음과 같은 경우에 적합합니다:**
- 비싼 외부 API에 대한 과도한 호출 방지
- 웹 검색 또는 데이터베이스 쿼리 제한
- 특정 도구 사용에 대한 속도 제한 적용
</Tip>

```python
from langchain.agents import create_agent
from langchain.agents.middleware import ToolCallLimitMiddleware

# 모든 도구 호출 제한
global_limiter = ToolCallLimitMiddleware(thread_limit=20, run_limit=10)

# 특정 도구 제한
search_limiter = ToolCallLimitMiddleware(
    tool_name="search",
    thread_limit=5,
    run_limit=3,
)

agent = create_agent(
    model="openai:gpt-4o",
    tools=[...],
    middleware=[global_limiter, search_limiter],
)
```




<Accordion title="구성 옵션">

<ParamField body="tool_name" type="string">
  제한할 특정 도구. 제공하지 않으면 모든 도구에 제한이 적용됩니다.
</ParamField>

<ParamField body="thread_limit" type="number">
  스레드의 모든 실행에서 최대 도구 호출 수. 기본값은 제한 없음입니다.
</ParamField>

<ParamField body="run_limit" type="number">
  단일 호출당 최대 도구 호출 수. 기본값은 제한 없음입니다.
</ParamField>

<ParamField body="exit_behavior" type="string" default="end">
  제한에 도달했을 때의 동작. 옵션: `"end"` (정상 종료) 또는 `"error"` (예외 발생)
</ParamField>




</Accordion>

### 모델 폴백

기본 모델이 실패할 때 대체 모델로 자동으로 폴백합니다.

<Tip>
**다음과 같은 경우에 적합합니다:**
- 모델 장애를 처리하는 복원력 있는 에이전트 구축
- 더 저렴한 모델로 폴백하여 비용 최적화
- OpenAI, Anthropic 등에 걸친 공급자 중복성
</Tip>

```python
from langchain.agents import create_agent
from langchain.agents.middleware import ModelFallbackMiddleware

agent = create_agent(
    model="openai:gpt-4o",  # 기본 모델
    tools=[...],
    middleware=[
        ModelFallbackMiddleware(
            "openai:gpt-4o-mini",  # 오류 시 먼저 시도
            "anthropic:claude-3-5-sonnet-20241022",  # 그 다음 이것
        ),
    ],
)
```




<Accordion title="구성 옵션">

<ParamField body="first_model" type="string | BaseChatModel" required>
  기본 모델이 실패할 때 시도할 첫 번째 폴백 모델. 모델 문자열(예: `"openai:gpt-4o-mini"`) 또는 `BaseChatModel` 인스턴스일 수 있습니다.
</ParamField>

<ParamField body="*additional_models" type="string | BaseChatModel">
  이전 모델이 실패할 경우 순서대로 시도할 추가 폴백 모델
</ParamField>




</Accordion>

### PII 탐지

대화에서 개인 식별 정보를 탐지하고 처리합니다.

<Tip>
**다음과 같은 경우에 적합합니다:**
- 규정 준수 요구사항이 있는 의료 및 금융 애플리케이션
- 로그를 정화해야 하는 고객 서비스 에이전트
- 민감한 사용자 데이터를 처리하는 모든 애플리케이션
</Tip>

```python
from langchain.agents import create_agent
from langchain.agents.middleware import PIIMiddleware

agent = create_agent(
    model="openai:gpt-4o",
    tools=[...],
    middleware=[
        # 사용자 입력의 이메일 수정
        PIIMiddleware("email", strategy="redact", apply_to_input=True),
        # 신용카드 마스킹 (마지막 4자리 표시)
        PIIMiddleware("credit_card", strategy="mask", apply_to_input=True),
        # 정규식을 사용한 커스텀 PII 유형
        PIIMiddleware(
            "api_key",
            detector=r"sk-[a-zA-Z0-9]{32}",
            strategy="block",  # 탐지 시 오류 발생
        ),
    ],
)
```




<Accordion title="구성 옵션">

<ParamField body="pii_type" type="string" required>
  탐지할 PII 유형. 내장 유형(`email`, `credit_card`, `ip`, `mac_address`, `url`) 또는 커스텀 유형 이름일 수 있습니다.
</ParamField>

<ParamField body="strategy" type="string" default="redact">
  탐지된 PII를 처리하는 방법. 옵션:
  - `"block"` - 탐지 시 예외 발생
  - `"redact"` - `[REDACTED_TYPE]`으로 교체
  - `"mask"` - 부분 마스킹 (예: `****-****-****-1234`)
  - `"hash"` - 결정론적 해시로 교체
</ParamField>

<ParamField body="detector" type="function | regex">
  커스텀 탐지기 함수 또는 정규식 패턴. 제공하지 않으면 PII 유형에 대한 내장 탐지기를 사용합니다.
</ParamField>

<ParamField body="apply_to_input" type="boolean" default="True">
  모델 호출 전 사용자 메시지 확인
</ParamField>

<ParamField body="apply_to_output" type="boolean" default="False">
  모델 호출 후 AI 메시지 확인
</ParamField>

<ParamField body="apply_to_tool_results" type="boolean" default="False">
  실행 후 도구 결과 메시지 확인
</ParamField>




</Accordion>

### 계획(Planning)

복잡한 다단계 작업을 위한 할 일 목록 관리 기능을 추가합니다.

<Note>
이 middleware는 에이전트에 `write_todos` 도구와 효과적인 작업 계획을 안내하는 시스템 프롬프트를 자동으로 제공합니다.
</Note>

```python
from langchain.agents import create_agent
from langchain.agents.middleware import PlanningMiddleware
from langchain.messages import HumanMessage

agent = create_agent(
    model="openai:gpt-4o",
    tools=[...],
    middleware=[PlanningMiddleware()],
)

result = agent.invoke({"messages": [HumanMessage("Help me refactor my codebase")]})
print(result["todos"])  # 상태 추적이 있는 할 일 항목 배열
```




<Accordion title="구성 옵션">

<ParamField body="system_prompt" type="string">
  할 일 사용을 안내하는 커스텀 시스템 프롬프트. 지정하지 않으면 내장 프롬프트를 사용합니다.
</ParamField>

<ParamField body="tool_description" type="string">
  `write_todos` 도구에 대한 커스텀 설명. 지정하지 않으면 내장 설명을 사용합니다.
</ParamField>




</Accordion>

### LLM 도구 선택기

기본 모델을 호출하기 전에 LLM을 사용하여 관련 도구를 지능적으로 선택합니다.

<Tip>
**다음과 같은 경우에 적합합니다:**
- 쿼리당 대부분이 관련 없는 많은 도구(10개 이상)를 가진 에이전트
- 관련 없는 도구를 필터링하여 토큰 사용량 감소
- 모델 집중도 및 정확도 향상
</Tip>

```python
from langchain.agents import create_agent
from langchain.agents.middleware import LLMToolSelectorMiddleware

agent = create_agent(
    model="openai:gpt-4o",
    tools=[tool1, tool2, tool3, tool4, tool5, ...],  # 많은 도구
    middleware=[
        LLMToolSelectorMiddleware(
            model="openai:gpt-4o-mini",  # 선택에 더 저렴한 모델 사용
            max_tools=3,  # 가장 관련성 높은 3개 도구로 제한
            always_include=["search"],  # 특정 도구는 항상 포함
        ),
    ],
)
```




<Accordion title="구성 옵션">

<ParamField body="model" type="string | BaseChatModel">
  도구 선택을 위한 모델. 모델 문자열 또는 `BaseChatModel` 인스턴스일 수 있습니다. 기본값은 에이전트의 주 모델입니다.
</ParamField>

<ParamField body="system_prompt" type="string">
  선택 모델을 위한 지침. 지정하지 않으면 내장 프롬프트를 사용합니다.
</ParamField>

<ParamField body="max_tools" type="number">
  선택할 최대 도구 수. 기본값은 제한 없음입니다.
</ParamField>

<ParamField body="always_include" type="list[string]">
  항상 선택에 포함할 도구 이름 목록
</ParamField>




</Accordion>

### 도구 재시도

구성 가능한 지수 백오프로 실패한 도구 호출을 자동으로 재시도합니다.

<Tip>
**다음과 같은 경우에 적합합니다:**
- 외부 API 호출의 일시적 실패 처리
- 네트워크에 의존하는 도구의 안정성 향상
- 일시적 오류를 우아하게 처리하는 복원력 있는 에이전트 구축
</Tip>

```python
from langchain.agents import create_agent
from langchain.agents.middleware import ToolRetryMiddleware

agent = create_agent(
    model="openai:gpt-4o",
    tools=[search_tool, database_tool],
    middleware=[
        ToolRetryMiddleware(
            max_retries=3,  # 최대 3회 재시도
            backoff_factor=2.0,  # 지수 백오프 승수
            initial_delay=1.0,  # 1초 지연으로 시작
            max_delay=60.0,  # 지연을 60초로 제한
            jitter=True,  # 랜덤 지터를 추가하여 thundering herd 방지
        ),
    ],
)
```

<Accordion title="구성 옵션">

<ParamField body="max_retries" type="number" default="2">
  초기 호출 후 최대 재시도 횟수 (기본값으로 총 3회 시도)
</ParamField>

<ParamField body="tools" type="list[BaseTool | str]">
  재시도 로직을 적용할 도구 또는 도구 이름의 선택적 목록. `None`이면 모든 도구에 적용됩니다.
</ParamField>

<ParamField body="retry_on" type="tuple[type[Exception], ...] | callable" default="(Exception,)">
  재시도할 예외 유형의 튜플 또는 예외를 받아 재시도해야 하는 경우 `True`를 반환하는 호출 가능한 함수.
</ParamField>

<ParamField body="on_failure" type="string | callable" default="return_message">
  모든 재시도가 소진되었을 때의 동작. 옵션:
  - `"return_message"` - 오류 세부 정보가 포함된 ToolMessage 반환 (LLM이 실패를 처리하도록 허용)
  - `"raise"` - 예외 재발생 (에이전트 실행 중지)
  - 커스텀 호출 가능 - 예외를 받아 ToolMessage 콘텐츠용 문자열을 반환하는 함수
</ParamField>

<ParamField body="backoff_factor" type="number" default="2.0">
  지수 백오프를 위한 승수. 각 재시도는 `initial_delay * (backoff_factor ** retry_number)` 초를 기다립니다. 일정한 지연을 위해 0.0으로 설정합니다.
</ParamField>

<ParamField body="initial_delay" type="number" default="1.0">
  첫 번째 재시도 전 초기 지연(초)
</ParamField>

<ParamField body="max_delay" type="number" default="60.0">
  재시도 간 최대 지연(초) (지수 백오프 증가를 제한)
</ParamField>

<ParamField body="jitter" type="boolean" default="true">
  thundering herd를 방지하기 위해 지연에 랜덤 지터(±25%)를 추가할지 여부
</ParamField>

</Accordion>



### LLM 도구 에뮬레이터

테스트 목적으로 LLM을 사용하여 도구 실행을 에뮬레이트하고, 실제 도구 호출을 AI 생성 응답으로 대체합니다.

<Tip>
**다음과 같은 경우에 적합합니다:**
- 실제 도구를 실행하지 않고 에이전트 동작 테스트
- 외부 도구를 사용할 수 없거나 비용이 많이 드는 경우 에이전트 개발
- 실제 도구를 구현하기 전에 에이전트 워크플로 프로토타이핑
</Tip>

```python
from langchain.agents import create_agent
from langchain.agents.middleware import LLMToolEmulator

agent = create_agent(
    model="openai:gpt-4o",
    tools=[get_weather, search_database, send_email],
    middleware=[
        # 기본적으로 모든 도구 에뮬레이트
        LLMToolEmulator(),

        # 또는 특정 도구 에뮬레이트
        # LLMToolEmulator(tools=["get_weather", "search_database"]),

        # 또는 에뮬레이션에 커스텀 모델 사용
        # LLMToolEmulator(model="anthropic:claude-3-5-sonnet-latest"),
    ],
)
```

<Accordion title="구성 옵션">

<ParamField body="tools" type="list[str | BaseTool]">
  에뮬레이트할 도구 이름(str) 또는 BaseTool 인스턴스의 목록. `None`(기본값)이면 모든 도구가 에뮬레이트됩니다. 빈 목록이면 도구가 에뮬레이트되지 않습니다.

</ParamField>

## 커스텀 middleware

에이전트 실행 흐름의 특정 지점에서 실행되는 훅을 구현하여 커스텀 middleware를 구축합니다.

두 가지 방법으로 middleware를 생성할 수 있습니다:
1. **데코레이터 기반** - 단일 훅 middleware를 위한 빠르고 간단한 방법
2. **클래스 기반** - 여러 훅이 있는 복잡한 middleware를 위한 더 강력한 방법

## 데코레이터 기반 middleware

단일 훅만 필요한 간단한 middleware의 경우, 데코레이터가 기능을 추가하는 가장 빠른 방법을 제공합니다:

```python
from langchain.agents.middleware import before_model, after_model, wrap_model_call
from langchain.agents.middleware import AgentState, ModelRequest, ModelResponse, dynamic_prompt
from langchain.messages import AIMessage
from langchain.agents import create_agent
from langgraph.runtime import Runtime
from typing import Any, Callable

# 노드 스타일: 모델 호출 전 로깅
@before_model
def log_before_model(state: AgentState, runtime: Runtime) -> dict[str, Any] | None:
    print(f"About to call model with {len(state['messages'])} messages")
    return None

# 노드 스타일: 모델 호출 후 검증
@after_model(can_jump_to=["end"])
def validate_output(state: AgentState, runtime: Runtime) -> dict[str, Any] | None:
    last_message = state["messages"][-1]
    if "BLOCKED" in last_message.content:
        return {
            "messages": [AIMessage("I cannot respond to that request.")],
            "jump_to": "end"
        }
    return None

# 래핑 스타일: 재시도 로직
@wrap_model_call
def retry_model(
    request: ModelRequest,
    handler: Callable[[ModelRequest], ModelResponse],
) -> ModelResponse:
    for attempt in range(3):
        try:
            return handler(request)
        except Exception as e:
            if attempt == 2:
                raise
            print(f"Retry {attempt + 1}/3 after error: {e}")

# 래핑 스타일: 동적 프롬프트
@dynamic_prompt
def personalized_prompt(request: ModelRequest) -> str:
    user_id = request.runtime.context.get("user_id", "guest")
    return f"You are a helpful assistant for user {user_id}. Be concise and friendly."

# 에이전트에서 데코레이터 사용
agent = create_agent(
    model="openai:gpt-4o",
    middleware=[log_before_model, validate_output, retry_model, personalized_prompt],
    tools=[...],
)
```

### 사용 가능한 데코레이터

**노드 스타일** (특정 실행 지점에서 실행):
- `@before_agent` - 에이전트 시작 전 (호출당 한 번)
- [`@before_model`](https://reference.langchain.com/python/langchain/middleware/#langchain.agents.middleware.before_model) - 각 모델 호출 전
- [`@after_model`](https://reference.langchain.com/python/langchain/middleware/#langchain.agents.middleware.after_model) - 각 모델 응답 후
- `@after_agent` - 에이전트 완료 후 (호출당 한 번)

**래핑 스타일** (실행을 가로채고 제어):
- [`@wrap_model_call`](https://reference.langchain.com/python/langchain/middleware/#langchain.agents.middleware.wrap_model_call) - 각 모델 호출 주변
- [`@wrap_tool_call`](https://reference.langchain.com/python/langchain/middleware/#langchain.agents.middleware.wrap_tool_call) - 각 도구 호출 주변

**편의 데코레이터**:
- [`@dynamic_prompt`](https://reference.langchain.com/python/langchain/middleware/#langchain.agents.middleware.dynamic_prompt) - 동적 시스템 프롬프트 생성 (프롬프트를 수정하는 [`@wrap_model_call`](https://reference.langchain.com/python/langchain/middleware/#langchain.agents.middleware.wrap_model_call)과 동등)

## 클래스 기반 middleware

### 두 가지 훅 스타일

<CardGroup cols={2}>
  <Card title="노드 스타일 훅" icon="diagram-project">
    특정 실행 지점에서 순차적으로 실행됩니다. 로깅, 검증 및 상태 업데이트에 사용합니다.
  </Card>
  <Card title="래핑 스타일 훅" icon="arrows-rotate">
    핸들러 호출을 완전히 제어하며 실행을 가로챕니다. 재시도, 캐싱 및 변환에 사용합니다.
  </Card>
</CardGroup>

#### 노드 스타일 훅

실행 흐름의 특정 지점에서 실행됩니다:

- `before_agent` - 에이전트 시작 전 (호출당 한 번)
- `before_model` - 각 모델 호출 전
- `after_model` - 각 모델 응답 후
- `after_agent` - 에이전트 완료 후 (호출당 최대 한 번)




**예시: 로깅 middleware**

```python
from langchain.agents.middleware import AgentMiddleware, AgentState
from langgraph.runtime import Runtime
from typing import Any

class LoggingMiddleware(AgentMiddleware):
    def before_model(self, state: AgentState, runtime: Runtime) -> dict[str, Any] | None:
        print(f"About to call model with {len(state['messages'])} messages")
        return None

    def after_model(self, state: AgentState, runtime: Runtime) -> dict[str, Any] | None:
        print(f"Model returned: {state['messages'][-1].content}")
        return None
```




**예시: 대화 길이 제한**

```python
from langchain.agents.middleware import AgentMiddleware, AgentState
from langchain.messages import AIMessage
from langgraph.runtime import Runtime
from typing import Any

class MessageLimitMiddleware(AgentMiddleware):
    def __init__(self, max_messages: int = 50):
        super().__init__()
        self.max_messages = max_messages

    def before_model(self, state: AgentState, runtime: Runtime) -> dict[str, Any] | None:
        if len(state["messages"]) == self.max_messages:
            return {
                "messages": [AIMessage("Conversation limit reached.")],
                "jump_to": "end"
            }
        return None
```




#### 래핑 스타일 훅

실행을 가로채고 핸들러가 호출되는 시점을 제어합니다:

- `wrap_model_call` - 각 모델 호출 주변
- `wrap_tool_call` - 각 도구 호출 주변




핸들러가 0번 호출되는지(단락), 1번 호출되는지(정상 흐름), 여러 번 호출되는지(재시도 로직)를 결정합니다.

**예시: 모델 재시도 middleware**

```python
from langchain.agents.middleware import AgentMiddleware, ModelRequest, ModelResponse
from typing import Callable

class RetryMiddleware(AgentMiddleware):
    def __init__(self, max_retries: int = 3):
        super().__init__()
        self.max_retries = max_retries

    def wrap_model_call(
        self,
        request: ModelRequest,
        handler: Callable[[ModelRequest], ModelResponse],
    ) -> ModelResponse:
        for attempt in range(self.max_retries):
            try:
                return handler(request)
            except Exception as e:
                if attempt == self.max_retries - 1:
                    raise
                print(f"Retry {attempt + 1}/{self.max_retries} after error: {e}")
```




**예시: 동적 모델 선택**

```python
from langchain.agents.middleware import AgentMiddleware, ModelRequest, ModelResponse
from langchain.chat_models import init_chat_model
from typing import Callable

class DynamicModelMiddleware(AgentMiddleware):
    def wrap_model_call(
        self,
        request: ModelRequest,
        handler: Callable[[ModelRequest], ModelResponse],
    ) -> ModelResponse:
        # 대화 길이에 따라 다른 모델 사용
        if len(request.messages) > 10:
            request.model = init_chat_model("openai:gpt-4o")
        else:
            request.model = init_chat_model("openai:gpt-4o-mini")

        return handler(request)
```




**예시: 도구 호출 모니터링**

```python
from langchain.tools.tool_node import ToolCallRequest
from langchain.agents.middleware import AgentMiddleware
from langchain_core.messages import ToolMessage
from langgraph.types import Command
from typing import Callable

class ToolMonitoringMiddleware(AgentMiddleware):
    def wrap_tool_call(
        self,
        request: ToolCallRequest,
        handler: Callable[[ToolCallRequest], ToolMessage | Command],
    ) -> ToolMessage | Command:
        print(f"Executing tool: {request.tool_call['name']}")
        print(f"Arguments: {request.tool_call['args']}")

        try:
            result = handler(request)
            print(f"Tool completed successfully")
            return result
        except Exception as e:
            print(f"Tool failed: {e}")
            raise
```




### 커스텀 상태 스키마

Middleware는 커스텀 속성으로 에이전트의 상태를 확장할 수 있습니다. 커스텀 상태 유형을 정의하고 `state_schema`로 설정합니다:

```python
from langchain.agents.middleware import AgentState, AgentMiddleware
from typing_extensions import NotRequired
from typing import Any

class CustomState(AgentState):
    model_call_count: NotRequired[int]
    user_id: NotRequired[str]

class CallCounterMiddleware(AgentMiddleware[CustomState]):
    state_schema = CustomState

    def before_model(self, state: CustomState, runtime) -> dict[str, Any] | None:
        # 커스텀 상태 속성 접근
        count = state.get("model_call_count", 0)

        if count > 10:
            return {"jump_to": "end"}

        return None

    def after_model(self, state: CustomState, runtime) -> dict[str, Any] | None:
        # 커스텀 상태 업데이트
        return {"model_call_count": state.get("model_call_count", 0) + 1}
```




```python
agent = create_agent(
    model="openai:gpt-4o",
    middleware=[CallCounterMiddleware()],
    tools=[...],
)

# 커스텀 상태로 호출
result = agent.invoke({
    "messages": [HumanMessage("Hello")],
    "model_call_count": 0,
    "user_id": "user-123",
})
```







### 실행 순서

여러 middleware를 사용할 때 실행 순서를 이해하는 것이 중요합니다:

```python
agent = create_agent(
    model="openai:gpt-4o",
    middleware=[middleware1, middleware2, middleware3],
    tools=[...],
)
```




<Accordion title="실행 흐름 (확장하려면 클릭)">

**Before 훅은 순서대로 실행:**

1. `middleware1.before_agent()`
2. `middleware2.before_agent()`
3. `middleware3.before_agent()`

__에이전트 루프 시작__

5. `middleware1.before_model()`
6. `middleware2.before_model()`
7. `middleware3.before_model()`

**Wrap 훅은 함수 호출처럼 중첩:**

8. `middleware1.wrap_model_call()` → `middleware2.wrap_model_call()` → `middleware3.wrap_model_call()` → model

**After 훅은 역순으로 실행:**

9. `middleware3.after_model()`
10. `middleware2.after_model()`
11. `middleware1.after_model()`

__에이전트 루프 종료__

13. `middleware3.after_agent()`
14. `middleware2.after_agent()`
15. `middleware1.after_agent()`

</Accordion>

**주요 규칙:**
- `before_*` 훅: 처음부터 마지막까지
- `after_*` 훅: 마지막부터 처음까지 (역순)
- `wrap_*` 훅: 중첩됨 (첫 번째 middleware가 다른 모든 것을 감쌈)

### 에이전트 점프

middleware에서 조기에 종료하려면 `jump_to`가 포함된 딕셔너리를 반환합니다:

```python
class EarlyExitMiddleware(AgentMiddleware):
    def before_model(self, state: AgentState, runtime) -> dict[str, Any] | None:
        # 조건 확인
        if should_exit(state):
            return {
                "messages": [AIMessage("Exiting early due to condition.")],
                "jump_to": "end"
            }
        return None
```




사용 가능한 점프 대상:

- `"end"`: 에이전트 실행의 끝으로 점프
- `"tools"`: 도구 노드로 점프
- `"model"`: 모델 노드로 점프 (또는 첫 번째 `before_model` 훅)

**중요:** `before_model` 또는 `after_model`에서 점프할 때 `"model"`로 점프하면 모든 `before_model` middleware가 다시 실행됩니다.

점프를 활성화하려면 훅을 `@hook_config(can_jump_to=[...])`로 데코레이트합니다:

```python
from langchain.agents.middleware import AgentMiddleware, hook_config
from typing import Any

class ConditionalMiddleware(AgentMiddleware):
    @hook_config(can_jump_to=["end", "tools"])
    def after_model(self, state: AgentState, runtime) -> dict[str, Any] | None:
        if some_condition(state):
            return {"jump_to": "end"}
        return None
```




### 모범 사례

1. Middleware를 집중적으로 유지 - 각각은 한 가지를 잘 수행해야 합니다
2. 오류를 우아하게 처리 - middleware 오류가 에이전트를 충돌시키지 않도록 합니다
3. **적절한 훅 유형 사용**:
    - 순차 로직을 위한 노드 스타일 (로깅, 검증)
    - 제어 흐름을 위한 래핑 스타일 (재시도, 폴백, 캐싱)
4. 커스텀 상태 속성을 명확하게 문서화합니다
5. 통합하기 전에 middleware를 독립적으로 단위 테스트합니다
6. 실행 순서 고려 - 중요한 middleware를 목록의 첫 번째에 배치합니다
7. 가능한 경우 내장 middleware 사용 - 바퀴를 재발명하지 마세요 :)

### 도구를 동적으로 선택하기

런타임에 관련 도구를 선택하여 성능과 정확도를 향상시킵니다.

<Tip>
**이점:**
- **더 짧은 프롬프트** - 관련 도구만 노출하여 복잡성 감소
- **더 나은 정확도** - 모델이 더 적은 옵션에서 올바르게 선택
- **권한 제어** - 사용자 액세스에 따라 도구를 동적으로 필터링
</Tip>

```python
from langchain.agents import create_agent
from langchain.agents.middleware import AgentMiddleware, ModelRequest
from typing import Callable

class ToolSelectorMiddleware(AgentMiddleware):
    def wrap_model_call(
        self,
        request: ModelRequest,
        handler: Callable[[ModelRequest], ModelResponse],
    ) -> ModelResponse:
        """상태/컨텍스트를 기반으로 관련 도구를 선택하는 Middleware."""
        # 상태/컨텍스트를 기반으로 작고 관련성 높은 도구 하위 집합 선택
        relevant_tools = select_relevant_tools(request.state, request.runtime)
        request.tools = relevant_tools
        return handler(request)

agent = create_agent(
    model="openai:gpt-4o",
    tools=all_tools,  # 모든 사용 가능한 도구를 미리 등록해야 합니다
    # Middleware를 사용하여 주어진 실행에 관련된 더 작은 하위 집합을 선택할 수 있습니다.
    middleware=[ToolSelectorMiddleware()],
)
```




<Expandable title="확장 예제: GitHub vs GitLab 도구 선택">

```python
from dataclasses import dataclass
from typing import Literal, Callable

from langchain.agents import create_agent
from langchain.agents.middleware import AgentMiddleware, ModelRequest, ModelResponse
from langchain_core.tools import tool

@tool
def github_create_issue(repo: str, title: str) -> dict:
    """GitHub 저장소에 이슈를 생성합니다."""
    return {"url": f"https://github.com/{repo}/issues/1", "title": title}

@tool
def gitlab_create_issue(project: str, title: str) -> dict:
    """GitLab 프로젝트에 이슈를 생성합니다."""
    return {"url": f"https://gitlab.com/{project}/-/issues/1", "title": title}

all_tools = [github_create_issue, gitlab_create_issue]

@dataclass
class Context:
    provider: Literal["github", "gitlab"]

class ToolSelectorMiddleware(AgentMiddleware):
    def wrap_model_call(
        self,
        request: ModelRequest,
        handler: Callable[[ModelRequest], ModelResponse],
    ) -> ModelResponse:
        """VCS 공급자를 기반으로 도구를 선택합니다."""
        provider = request.runtime.context.provider

        if provider == "gitlab":
            selected_tools = [t for t in request.tools if t.name == "gitlab_create_issue"]
        else:
            selected_tools = [t for t in request.tools if t.name == "github_create_issue"]

        request.tools = selected_tools
        return handler(request)

agent = create_agent(
    model="openai:gpt-4o",
    tools=all_tools,
    middleware=[ToolSelectorMiddleware()],
    context_schema=Context,
)

# GitHub 컨텍스트로 호출
agent.invoke(
    {
        "messages": [{"role": "user", "content": "Open an issue titled 'Bug: where are the cats' in the repository `its-a-cats-game`"}]
    },
    context=Context(provider="github"),
)
```




**주요 포인트:**
- 모든 도구를 미리 등록
- Middleware가 요청당 관련 하위 집합을 선택
- 구성 요구사항에 `context_schema` 사용
