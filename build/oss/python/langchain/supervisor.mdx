## 개요

**supervisor 패턴**은 중앙 supervisor 에이전트가 전문화된 worker 에이전트들을 조정하는 [멀티 에이전트](/oss/python/langchain/multi-agent) 아키텍처입니다. 이 접근 방식은 작업에 서로 다른 유형의 전문 지식이 필요할 때 뛰어납니다. 여러 도메인에 걸쳐 도구 선택을 관리하는 하나의 에이전트를 구축하는 대신, supervisor가 전체 워크플로우를 이해하고 조정하는 집중된 전문가들을 만듭니다.

이 튜토리얼에서는 현실적인 워크플로우를 통해 이러한 이점을 보여주는 개인 비서 시스템을 구축합니다. 시스템은 근본적으로 다른 책임을 가진 두 전문가를 조정합니다:

- 일정 관리, 가용성 확인 및 이벤트 관리를 처리하는 **캘린더 에이전트**.
- 커뮤니케이션, 메시지 초안 작성 및 알림 전송을 관리하는 **이메일 에이전트**.

또한 사용자가 원하는 대로 작업(예: 발신 이메일)을 승인, 편집 및 거부할 수 있도록 [human-in-the-loop 검토](/oss/python/langchain/human-in-the-loop)를 통합합니다.

### Supervisor를 사용하는 이유

멀티 에이전트 아키텍처를 사용하면 [도구](/oss/python/langchain/tools)를 worker들에 분산하여 각각 자체 프롬프트 또는 지시사항을 가질 수 있습니다. 모든 캘린더 및 이메일 API에 직접 액세스할 수 있는 에이전트를 고려해 보세요: 이 에이전트는 많은 유사한 도구 중에서 선택하고, 각 API의 정확한 형식을 이해하며, 여러 도메인을 동시에 처리해야 합니다. 성능이 저하되면 관련 도구와 관련 프롬프트를 논리적 그룹으로 분리하는 것이 도움이 될 수 있습니다(부분적으로 반복적인 개선을 관리하기 위해).

## 1. 도구 정의

구조화된 입력이 필요한 도구를 정의하는 것부터 시작하세요. 실제 애플리케이션에서는 실제 API(Google Calendar, SendGrid 등)를 호출할 것입니다. 이 튜토리얼에서는 스텁을 사용하여 패턴을 시연합니다.

```python
from langchain_core.tools import tool

@tool
def create_calendar_event(
    title: str,
    start_time: str,       # ISO 형식: "2024-01-15T14:00:00"
    end_time: str,         # ISO 형식: "2024-01-15T15:00:00"
    attendees: list[str],  # 이메일 주소
    location: str = ""
) -> str:
    """캘린더 이벤트를 생성합니다. 정확한 ISO datetime 형식이 필요합니다."""
    # 스텁: 실제로는 Google Calendar API, Outlook API 등을 호출합니다.
    return f"Event created: {title} from {start_time} to {end_time} with {len(attendees)} attendees"


@tool
def send_email(
    to: list[str],  # 이메일 주소
    subject: str,
    body: str,
    cc: list[str] = []
) -> str:
    """이메일 API를 통해 이메일을 전송합니다. 올바른 형식의 주소가 필요합니다."""
    # 스텁: 실제로는 SendGrid, Gmail API 등을 호출합니다.
    return f"Email sent to {', '.join(to)} - Subject: {subject}"


@tool
def get_available_time_slots(
    attendees: list[str],
    date: str,  # ISO 형식: "2024-01-15"
    duration_minutes: int
) -> list[str]:
    """특정 날짜에 주어진 참석자의 캘린더 가용성을 확인합니다."""
    # 스텁: 실제로는 캘린더 API를 쿼리합니다.
    return ["09:00", "14:00", "16:00"]
```

## 2. 전문화된 서브 에이전트 생성

다음으로 각 도메인을 처리하는 전문화된 서브 에이전트를 생성합니다.

### 캘린더 에이전트 생성

캘린더 에이전트는 자연어 일정 요청을 이해하고 정확한 API 호출로 변환합니다. 날짜 파싱, 가용성 확인 및 이벤트 생성을 처리합니다.

```python
from langchain.agents import create_agent

CALENDAR_AGENT_PROMPT = (
    "You are a calendar scheduling assistant. "
    "Parse natural language scheduling requests (e.g., 'next Tuesday at 2pm') "
    "into proper ISO datetime formats. "
    "Use get_available_time_slots to check availability when needed. "
    "Use create_calendar_event to schedule events. "
    "Always confirm what was scheduled in your final response."
)

calendar_agent = create_agent(
    llm,
    tools=[create_calendar_event, get_available_time_slots],
    system_prompt=CALENDAR_AGENT_PROMPT,
)
```

캘린더 에이전트를 테스트하여 자연어 일정을 어떻게 처리하는지 확인하세요:

```python
query = "Schedule a team meeting next Tuesday at 2pm for 1 hour"

for step in calendar_agent.stream(

):
    for update in step.values():

            message.pretty_print()
```

### 이메일 에이전트 생성

이메일 에이전트는 메시지 작성 및 전송을 처리합니다. 수신자 정보 추출, 적절한 제목 및 본문 텍스트 작성, 이메일 커뮤니케이션 관리에 중점을 둡니다.

```python
EMAIL_AGENT_PROMPT = (
    "You are an email assistant. "
    "Compose professional emails based on natural language requests. "
    "Extract recipient information and craft appropriate subject lines and body text. "
    "Use send_email to send the message. "
    "Always confirm what was sent in your final response."
)

email_agent = create_agent(
    llm,
    tools=[send_email],
    system_prompt=EMAIL_AGENT_PROMPT,
)
```

자연어 요청으로 이메일 에이전트를 테스트하세요:

## 3. 서브 에이전트를 도구로 래핑

이제 각 서브 에이전트를 supervisor가 호출할 수 있는 도구로 래핑합니다. 이것이 계층화된 시스템을 만드는 핵심 아키텍처 단계입니다. Supervisor는 "create_calendar_event"와 같은 낮은 수준의 도구가 아니라 "schedule_event"와 같은 높은 수준의 도구를 보게 됩니다.

```python
@tool
def schedule_event(request: str) -> str:
    """자연어를 사용하여 캘린더 이벤트를 예약합니다.

    사용자가 캘린더 약속을 생성, 수정 또는 확인하려는 경우 사용합니다.
    날짜/시간 파싱, 가용성 확인 및 이벤트 생성을 처리합니다.

    입력: 자연어 일정 요청(예: 'meeting with design team
    next Tuesday at 2pm')
    """
    result = calendar_agent.invoke({
        "messages": [{"role": "user", "content": request}]
    })
    return result["messages"][-1].text


@tool
def manage_email(request: str) -> str:
    """자연어를 사용하여 이메일을 전송합니다.

    사용자가 알림, 리마인더 또는 이메일 커뮤니케이션을 전송하려는 경우 사용합니다.
    수신자 추출, 제목 생성 및 이메일 작성을 처리합니다.

    입력: 자연어 이메일 요청(예: 'send them a reminder about
    the meeting')
    """
    result = email_agent.invoke({
        "messages": [{"role": "user", "content": request}]
    })
    return result["messages"][-1].text
```

도구 설명은 supervisor가 각 도구를 언제 사용할지 결정하는 데 도움이 되므로 명확하고 구체적으로 작성하세요. supervisor는 중간 추론이나 도구 호출을 볼 필요가 없으므로 서브 에이전트의 최종 응답만 반환합니다.

## 4. Supervisor 에이전트 생성

이제 서브 에이전트를 조정하는 supervisor를 생성합니다. Supervisor는 높은 수준의 도구만 보고 개별 API 수준이 아닌 도메인 수준에서 라우팅 결정을 내립니다.

```python
SUPERVISOR_PROMPT = (
    "You are a helpful personal assistant. "
    "You can schedule calendar events and send emails. "
    "Break down user requests into appropriate tool calls and coordinate the results. "
    "When a request involves multiple actions, use multiple tools in sequence."
)

supervisor_agent = create_agent(
    llm,
    tools=[schedule_event, manage_email],
    system_prompt=SUPERVISOR_PROMPT,
)
```

### 완전한 작동 예제

다음은 실행 가능한 스크립트로 모든 것을 함께 정리한 것입니다:

<Expandable title="전체 코드 보기" defaultOpen={false}>

```python
"""
개인 비서 Supervisor 예제

이 예제는 멀티 에이전트 시스템을 위한 도구 호출 패턴을 보여줍니다.
Supervisor 에이전트가 도구로 래핑된 전문화된 서브 에이전트(캘린더 및 이메일)를
조정합니다.
"""

from langchain_core.tools import tool
from langchain.agents import create_agent
from langchain.chat_models import init_chat_model

# ============================================================================
# 단계 1: 낮은 수준의 API 도구 정의(스텁)
# ============================================================================

@tool
def create_calendar_event(
    title: str,
    start_time: str,  # ISO 형식: "2024-01-15T14:00:00"
    end_time: str,    # ISO 형식: "2024-01-15T15:00:00"
    attendees: list[str],  # 이메일 주소
    location: str = ""
) -> str:
    """캘린더 이벤트를 생성합니다. 정확한 ISO datetime 형식이 필요합니다."""
    return f"Event created: {title} from {start_time} to {end_time} with {len(attendees)} attendees"


@tool
def send_email(
    to: list[str],      # 이메일 주소
    subject: str,
    body: str,
    cc: list[str] = []
) -> str:
    """이메일 API를 통해 이메일을 전송합니다. 올바른 형식의 주소가 필요합니다."""
    return f"Email sent to {', '.join(to)} - Subject: {subject}"


@tool
def get_available_time_slots(
    attendees: list[str],
    date: str,  # ISO 형식: "2024-01-15"
    duration_minutes: int
) -> list[str]:
    """특정 날짜에 주어진 참석자의 캘린더 가용성을 확인합니다."""
    return ["09:00", "14:00", "16:00"]


# ============================================================================
# 단계 2: 전문화된 서브 에이전트 생성
# ============================================================================

llm = init_chat_model("anthropic:claude-3-5-haiku-latest")  # 예시

calendar_agent = create_agent(
    llm,
    tools=[create_calendar_event, get_available_time_slots],
    system_prompt=(
        "You are a calendar scheduling assistant. "
        "Parse natural language scheduling requests (e.g., 'next Tuesday at 2pm') "
        "into proper ISO datetime formats. "
        "Use get_available_time_slots to check availability when needed. "
        "Use create_calendar_event to schedule events. "
        "Always confirm what was scheduled in your final response."
    )
)

email_agent = create_agent(
    llm,
    tools=[send_email],
    system_prompt=(
        "You are an email assistant. "
        "Compose professional emails based on natural language requests. "
        "Extract recipient information and craft appropriate subject lines and body text. "
        "Use send_email to send the message. "
        "Always confirm what was sent in your final response."
    )
)

# ============================================================================
# 단계 3: Supervisor를 위한 도구로 서브 에이전트 래핑
# ============================================================================

@tool
def schedule_event(request: str) -> str:
    """자연어를 사용하여 캘린더 이벤트를 예약합니다.

    사용자가 캘린더 약속을 생성, 수정 또는 확인하려는 경우 사용합니다.
    날짜/시간 파싱, 가용성 확인 및 이벤트 생성을 처리합니다.

    입력: 자연어 일정 요청(예: 'meeting with design team
    next Tuesday at 2pm')
    """
    result = calendar_agent.invoke({
        "messages": [{"role": "user", "content": request}]
    })
    return result["messages"][-1].text


@tool
def manage_email(request: str) -> str:
    """자연어를 사용하여 이메일을 전송합니다.

    사용자가 알림, 리마인더 또는 이메일 커뮤니케이션을 전송하려는 경우 사용합니다.
    수신자 추출, 제목 생성 및 이메일 작성을 처리합니다.

    입력: 자연어 이메일 요청(예: 'send them a reminder about
    the meeting')
    """
    result = email_agent.invoke({
        "messages": [{"role": "user", "content": request}]
    })
    return result["messages"][-1].text


# ============================================================================
# 단계 4: Supervisor 에이전트 생성
# ============================================================================

supervisor_agent = create_agent(
    llm,
    tools=[schedule_event, manage_email],
    system_prompt=(
        "You are a helpful personal assistant. "
        "You can schedule calendar events and send emails. "
        "Break down user requests into appropriate tool calls and coordinate the results. "
        "When a request involves multiple actions, use multiple tools in sequence."
    )
)

# ============================================================================
# 단계 5: Supervisor 사용
# ============================================================================

if __name__ == "__main__":
    # 예제: 캘린더 및 이메일 조정이 필요한 사용자 요청
    user_request = (
        "Schedule a meeting with the design team next Tuesday at 2pm for 1 hour, "
        "and send them an email reminder about reviewing the new mockups."
    )

    print("User Request:", user_request)
    print("\n" + "="*80 + "\n")

    for step in supervisor_agent.stream(
        {"messages": [{"role": "user", "content": user_request}]}
    ):
        for update in step.values():
            for message in update.get("messages", []):
                message.pretty_print()
```

### 아키텍처 이해하기

시스템에는 세 개의 레이어가 있습니다. 하단 레이어에는 정확한 형식이 필요한 엄격한 API 도구가 포함되어 있습니다. 중간 레이어에는 자연어를 받아 구조화된 API 호출로 변환하고 자연어 확인을 반환하는 서브 에이전트가 포함되어 있습니다. 상단 레이어에는 높은 수준의 기능으로 라우팅하고 결과를 합성하는 supervisor가 포함되어 있습니다.

이러한 관심사의 분리는 여러 이점을 제공합니다: 각 레이어는 집중된 책임을 가지며, 기존 도메인에 영향을 주지 않고 새 도메인을 추가할 수 있으며, 각 레이어를 독립적으로 테스트하고 반복할 수 있습니다.

## 6. Human-in-the-loop 검토 추가

민감한 작업에 대해 [human-in-the-loop 검토](/oss/python/langchain/human-in-the-loop)를 통합하는 것이 현명할 수 있습니다. LangChain에는 도구 호출을 검토하기 위한 [내장 미들웨어](/oss/python/langchain/human-in-the-loop#configuring-interrupts)가 포함되어 있으며, 이 경우 서브 에이전트가 호출하는 도구입니다.

두 서브 에이전트에 human-in-the-loop 검토를 추가해 봅시다:
- 모든 [응답 유형](/oss/python/langchain/human-in-the-loop)(`approve`, `edit`, `reject`)을 허용하여 `create_calendar_event` 및 `send_email` 도구가 중단되도록 구성합니다
- 실행을 일시 중지하고 재개하는 데 필요한 **최상위 에이전트에만** [checkpointer](/oss/python/langchain/short-term-memory)를 추가합니다.

```python
from langchain.agents import create_agent
from langchain.agents.middleware import HumanInTheLoopMiddleware # [!code highlight]
from langgraph.checkpoint.memory import InMemorySaver # [!code highlight]

calendar_agent = create_agent(
    llm,
    tools=[create_calendar_event, get_available_time_slots],
    system_prompt=CALENDAR_AGENT_PROMPT,
    middleware=[ # [!code highlight]
        HumanInTheLoopMiddleware( # [!code highlight]
            interrupt_on={"create_calendar_event": True}, # [!code highlight]
            description_prefix="Calendar event pending approval", # [!code highlight]
        ), # [!code highlight]
    ], # [!code highlight]
)

email_agent = create_agent(
    llm,
    tools=[send_email],
    system_prompt=EMAIL_AGENT_PROMPT,
    middleware=[ # [!code highlight]
        HumanInTheLoopMiddleware( # [!code highlight]
            interrupt_on={"send_email": True}, # [!code highlight]
            description_prefix="Outbound email pending approval", # [!code highlight]
        ), # [!code highlight]
    ], # [!code highlight]
)

supervisor_agent = create_agent(
    llm,
    tools=[schedule_event, manage_email],
    system_prompt=SUPERVISOR_PROMPT,
    checkpointer=InMemorySaver(), # [!code highlight]
)
```

쿼리를 반복해 봅시다. 나중에 액세스하기 위해 interrupt 이벤트를 리스트에 수집합니다:
```python
query = (
    "Schedule a meeting with the design team next Tuesday at 2pm for 1 hour, "
    "and send them an email reminder about reviewing the new mockups."
)

config = {"configurable": {"thread_id": "6"}}

for step in supervisor_agent.stream(
    {"messages": [{"role": "user", "content": query}]},
    config,
):
    for update in step.values():
        if isinstance(update, dict):
            for message in update.get("messages", []):
                message.pretty_print()
        else:
            interrupt_ = update[0]
            interrupts.append(interrupt_)
            print(f"\nINTERRUPTED: {interrupt_.id}")
```

```python
from langgraph.types import Command # [!code highlight]

resume = {}
for interrupt_ in interrupts:
    if interrupt_.id == "2b56f299be313ad8bc689eff02973f16":
        # 이메일 편집
        edited_action = interrupt_.value["action_requests"][0].copy()
        edited_action["arguments"]["subject"] = "Mockups reminder"
        resume[interrupt_.id] = {
            "decisions": [{"type": "edit", "edited_action": edited_action}]
        }
    else:
        resume[interrupt_.id] = {"decisions": [{"type": "approve"}]}

interrupts = []
for step in supervisor_agent.stream(
    Command(resume=resume), # [!code highlight]
    config,
):
    for update in step.values():
        if isinstance(update, dict):
            for message in update.get("messages", []):
                message.pretty_print()

            interrupt_ = update[0]
```

## 7. 고급: 정보 흐름 제어

기본적으로 서브 에이전트는 supervisor로부터 요청 문자열만 받습니다. 대화 기록이나 사용자 기본 설정과 같은 추가 컨텍스트를 전달할 수 있습니다.

### 서브 에이전트에 추가 대화 컨텍스트 전달

```python
from typing import Annotated
from langchain.tools import InjectedState

@tool
def schedule_event(
    request: str,
    state: Annotated[dict, InjectedState]
) -> str:
    """자연어를 사용하여 캘린더 이벤트를 예약합니다."""
    # 서브 에이전트가 받는 컨텍스트 커스터마이징
    original_user_message = next(
        message for message in state["messages"]
        if message.type == "human"
    )
    prompt = (
        "You are assisting with the following user inquiry:\n\n"
        f"{original_user_message.text}\n\n"
        "You are tasked with the following sub-request:\n\n"
        f"{request}"
    )
    result = calendar_agent.invoke({
        "messages": [{"role": "user", "content": prompt}],
    })
    return result["messages"][-1].text
```

이를 통해 서브 에이전트가 전체 대화 컨텍스트를 볼 수 있으므로 "내일 같은 시간에 일정 잡아줘"(이전 대화 참조)와 같은 모호성을 해결하는 데 유용할 수 있습니다.

<Tip>
서브 에이전트가 받는 전체 컨텍스트는 LangSmith trace의 [chat model 호출](https://smith.langchain.com/public/c7d54882-afb8-4039-9c5a-4112d0f458b0/r/6803571e-af78-4c68-904a-ecf55771084d)에서 확인할 수 있습니다.
</Tip>

### Supervisor가 받는 것 제어

supervisor로 다시 흐르는 정보를 커스터마이징할 수도 있습니다:

```python
import json

@tool
def schedule_event(request: str) -> str:
    """자연어를 사용하여 캘린더 이벤트를 예약합니다."""
    result = calendar_agent.invoke({
        "messages": [{"role": "user", "content": request}]
    })

    # 옵션 1: 확인 메시지만 반환
    return result["messages"][-1].text

    # 옵션 2: 구조화된 데이터 반환
    # return json.dumps({
    #     "status": "success",
    #     "event_id": "evt_123",
    #     "summary": result["messages"][-1].text
    # })
```

**중요:** 서브 에이전트 프롬프트가 최종 메시지에 모든 관련 정보를 포함해야 한다는 것을 강조하세요. 일반적인 실패 모드는 도구 호출을 수행하지만 최종 응답에 결과를 포함하지 않는 서브 에이전트입니다.

## 8. 핵심 요점

Supervisor 패턴은 각 레이어가 명확한 책임을 가진 추상화 레이어를 만듭니다. Supervisor 시스템을 설계할 때 명확한 도메인 경계로 시작하고 각 서브 에이전트에 집중된 도구와 프롬프트를 제공하세요. Supervisor를 위한 명확한 도구 설명을 작성하고, 통합 전에 각 레이어를 독립적으로 테스트하며, 특정 요구 사항에 따라 정보 흐름을 제어하세요.

<Tip>
**Supervisor 패턴을 사용해야 하는 경우**

여러 개의 뚜렷한 도메인(캘린더, 이메일, CRM, 데이터베이스)이 있고, 각 도메인에 여러 도구 또는 복잡한 로직이 있으며, 중앙 집중식 워크플로우 제어를 원하고, 서브 에이전트가 사용자와 직접 대화할 필요가 없는 경우 supervisor 패턴을 사용하세요.

몇 가지 도구만 있는 간단한 경우에는 단일 에이전트를 사용하세요. 에이전트가 사용자와 대화해야 하는 경우 대신 [handoff](/oss/python/langchain/multi-agent#handoffs)를 사용하세요. 에이전트 간의 피어 투 피어 협업의 경우 다른 멀티 에이전트 패턴을 고려하세요.
</Tip>
