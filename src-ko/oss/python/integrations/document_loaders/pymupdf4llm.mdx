## 분할 모드 및 사용자 정의 페이지 구분자

PDF 파일을 로드할 때 두 가지 방법으로 분할할 수 있습니다:

- 페이지별
- 단일 텍스트 흐름

기본적으로 PyMuPDF4LLMLoader는 PDF를 페이지별로 분할합니다.

논리적으로 이 모드에서는 `page` (page_number) 메타데이터가 사라집니다. 다음은 텍스트 흐름에서 페이지가 끝나는 위치를 명확하게 식별하는 방법입니다:

### *single* 모드에서 페이지 끝 위치를 식별하기 위해 사용자 정의 *pages_delimiter*를 추가합니다

```python
loader = PyMuPDF4LLMLoader(
    "./example_data/layout-parser-paper.pdf",
    mode="single",
    pages_delimiter="\n-------THIS IS A CUSTOM END OF PAGE-------\n\n",
)
docs = loader.load()

part = docs[0].page_content[10663:11317]
print(part)
display(Markdown(part))
```

기본 `pages_delimiter`는 \n-----\n\n입니다.
하지만 단순히 \n이나 \f를 사용하여 페이지 변경을 명확하게 표시하거나, \<!-- PAGE BREAK -->를 사용하여 Markdown 뷰어에 시각적 효과 없이 원활하게 삽입할 수 있습니다.

# PDF에서 표 추출

PyMUPDF4LLM을 사용하면 PDF에서 *markdown* 형식으로 표를 추출할 수 있습니다:

```python
loader = PyMuPDF4LLMLoader(
    "./example_data/layout-parser-paper.pdf",
    mode="page",
    # "lines_strict"은 기본 전략이며
    # 열과 행 선이 있는 표에 가장 정확하지만
    # 모든 문서에서 잘 작동하지 않을 수 있습니다.
    # "lines"는 덜 엄격한 전략으로
    # 일부 문서에서 더 잘 작동할 수 있습니다.
    # "text"는 가장 덜 엄격한 전략으로
    # 선이 없는 표가 있는 문서에서 더 잘 작동할 수 있습니다.
    table_strategy="lines",
)
docs = loader.load()

part = docs[4].page_content[3210:]
print(part)
display(Markdown(part))
```

## 파일 작업

많은 문서 로더는 파일 파싱을 포함합니다. 이러한 로더 간의 차이는 일반적으로 파일이 로드되는 방식이 아니라 파일이 파싱되는 방식에서 비롯됩니다. 예를 들어, `open`을 사용하여 PDF나 마크다운 파일의 바이너리 콘텐츠를 읽을 수 있지만, 해당 바이너리 데이터를 텍스트로 변환하려면 다른 파싱 로직이 필요합니다.

결과적으로 파싱 로직과 로딩 로직을 분리하는 것이 도움이 될 수 있으며, 이를 통해 데이터가 로드되는 방식에 관계없이 주어진 파서를 더 쉽게 재사용할 수 있습니다.
이 전략을 사용하여 동일한 파싱 매개변수로 다른 파일을 분석할 수 있습니다.

```python
from langchain_community.document_loaders import FileSystemBlobLoader
from langchain_community.document_loaders.generic import GenericLoader
from langchain_pymupdf4llm import PyMuPDF4LLMParser

loader = GenericLoader(
    blob_loader=FileSystemBlobLoader(
        path="./example_data/",
        glob="*.pdf",
    ),
    blob_parser=PyMuPDF4LLMParser(),
)
docs = loader.load()

part = docs[0].page_content[:562]
print(part)
display(Markdown(part))
```
