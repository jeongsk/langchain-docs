Open Agent Platform이 기본적으로 사용하도록 구성된 인증 제공자는 Supabase입니다.

## Supabase 설정하기

Supabase 인증을 설정하려면 먼저 새로운 Supabase 프로젝트를 생성해야 합니다. 새 프로젝트를 생성한 후, `apps/web/` 디렉토리 내부에 다음 환경 변수를 설정하세요:

```bash
NEXT_PUBLIC_SUPABASE_URL="<your supabase url>"
NEXT_PUBLIC_SUPABASE_ANON_KEY="<your supabase anon key>"
```

Supabase 프로젝트에서 Google 인증도 활성화해야 합니다. Google 로그인을 허용하지 않으려면, 환경 변수에 `NEXT_PUBLIC_GOOGLE_AUTH_DISABLED=true`를 설정하여 UI에서 Google을 인증 옵션으로 표시하지 않도록 비활성화할 수 있습니다.

## LangGraph Server 인증

사전 구축된 LangGraph 에이전트는 사용자 정의 인증을 구현하므로, 해당 에이전트에 요청할 때 LangSmith API 키를 지정할 필요가 없습니다. 대신, 요청의 `Authorization` 헤더에 사용자의 Supabase 액세스 토큰(JWT 토큰)을 전달합니다.

LangGraph 서버의 인증 미들웨어 내부에서 이 토큰을 추출하고 Supabase를 통해 유효성을 검증합니다. 유효한 경우, 사용자 ID를 받아오며, 이를 사용하여 각 사용자가 *자신의* 에이전트와 스레드에만 접근할 수 있도록 검증합니다. 사용자가 자신이 생성하지 않은 에이전트에 접근할 수 있도록 허용하려면, LangGraph 서버의 사용자 정의 인증 미들웨어를 업데이트하여 사용자가 접근할 수 있도록 하려는 에이전트에 대한 접근을 허용해야 합니다.

`Authorization` 헤더와 함께, `x-supabase-access-token` 헤더를 통해서도 Supabase JWT를 중복으로 전달합니다. 이는 `x-`로 시작하는 모든 LangSmith 비특정 헤더가 LangGraph 서버로 전송될 때 스레드의 구성 가능한 필드에 포함되기 때문입니다. 이 JWT는 나중에 MCP 서버와 인증할 때 필요합니다.

## LangSmith API Key 인증

LangGraph 서버에서 사용자 정의 인증을 사용하지 *않고* 대신 누구나 에이전트에 접근할 수 있도록 허용하려면, `NEXT_PUBLIC_USE_LANGSMITH_AUTH` 환경 변수를 `true`로 설정하고, `apps/web/` 디렉토리 내부의 환경 변수에 `LANGSMITH_API_KEY`를 설정하면 됩니다.

마지막으로, `NEXT_PUBLIC_BASE_API_URL` 환경 변수가 **웹** 서버의 기본 API URL로 설정되어 있는지 확인하세요. 로컬 개발 환경에서는 다음과 같이 설정해야 합니다:

```bash
NEXT_PUBLIC_BASE_API_URL="http://localhost:3000/api"
```

이렇게 하면 웹 클라이언트로 전송되는 모든 요청이 먼저 프록시 라우트를 통과하게 되며, 이 라우트는 서버에서 LangSmith API 키를 요청에 주입하여 클라이언트에 API 키가 노출되지 않도록 합니다. 그런 다음 요청이 LangGraph 서버로 전달됩니다.

<Warning>
LangSmith API 키 환경 변수에는 `NEXT_PUBLIC_` 접두사를 *절대* 붙이지 마세요. 이것은 **비밀**이며 클라이언트에 노출되어서는 안 됩니다.
</Warning>

## RAG 인증

웹 클라이언트에서 LangConnect RAG 서버로의 인증은 LangGraph 인증과 유사한 방식으로 처리됩니다. 요청의 `Authorization` 헤더에 Supabase JWT를 전달합니다. 그런 다음 LangConnect RAG 서버 내부에서 이 토큰을 추출하고 Supabase를 통해 유효성을 검증합니다.

유효한 경우, 사용자 ID를 받아오며, 이를 사용하여 각 사용자가 *자신의* 컬렉션에만 접근할 수 있도록 검증합니다. 현재는 사용자 간 컬렉션 공유를 지원하지 않습니다.
