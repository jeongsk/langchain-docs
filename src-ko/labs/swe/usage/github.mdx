# GitHub 웹훅 통합

Open SWE는 웹훅을 통해 GitHub와 원활하게 통합되어, GitHub 이슈에서 직접 자동화된 코드 변경을 실행할 수 있습니다. Open SWE가 설치된 리포지토리의 이슈에 레이블을 추가하는 것만으로 코드 변경을 요청할 수 있는 효율적인 워크플로를 제공합니다.

## 레이블로 실행 트리거하기

Open SWE는 자동 실행을 트리거하는 특정 레이블이 있는지 GitHub 이슈를 모니터링합니다. 이러한 레이블 중 하나를 이슈에 추가하면, Open SWE가 자동으로 새 실행을 생성하여 요청을 처리합니다.

### 레이블 유형

Open SWE는 에이전트 작동 방식을 제어하는 세 가지 유형의 레이블을 지원합니다.

**수동 모드 (`open-swe`)**

- 코드 실행 전에 생성된 계획에 대한 수동 승인이 필요합니다
- 어떤 변경이 이루어질지 완전히 제어할 수 있습니다
- 복잡하거나 민감한 변경 사항에 대해 접근 방식을 먼저 검토하고 싶을 때 이상적입니다

**자동 모드 (`open-swe-auto`)**

- 생성된 계획을 자동으로 승인하고 실행합니다
- 간단한 요청에 대해 더 빠른 처리 시간을 제공합니다
- 단순한 변경이나 에이전트가 자율적으로 진행하도록 신뢰할 수 있을 때 가장 적합합니다

**최대 모드 (`open-swe-max` 및 `open-swe-max-auto`)**

- 계획 및 프로그래밍 작업 모두에 Claude Opus 4.1을 사용합니다
- 복잡한 문제에 대해 향상된 성능과 추론 능력을 제공합니다
- `open-swe-max`: 프리미엄 모델 성능으로 수동 계획 승인이 필요합니다
- `open-swe-max-auto`: 자동 실행과 프리미엄 모델 기능을 결합합니다
- 가장 고급 AI 추론의 이점을 받을 수 있는 어려운 작업에 이상적입니다

<Note>
  개발 환경에서는 각각 `open-swe-dev`, `open-swe-auto-dev`, `open-swe-max-dev`, `open-swe-max-auto-dev` 레이블을 사용합니다. 시스템은 `NODE_ENV` 환경 변수를 기반으로 적절한 레이블을 자동으로 사용합니다.
</Note>

## 자동 실행 생성

GitHub 이슈에 지원되는 레이블을 추가하면, Open SWE의 웹훅 핸들러가 자동으로 다음을 수행합니다:

1. **요청 검증** - 웹훅 서명과 인증을 확인합니다
2. **이슈 컨텍스트 추출** - 이슈 제목, 설명 및 메타데이터를 캡처합니다
3. **새 스레드 생성** - 대화를 위한 고유한 스레드 ID를 생성합니다
4. **Manager Graph 시작** - 이슈 내용으로 에이전트 워크플로를 시작합니다
5. **실행 모드 구성** - 사용된 레이블 유형에 따라 자동 승인을 설정합니다

전체 프로세스는 레이블 추가 후 몇 초 이내에 완료되며, 이슈 댓글을 통해 즉각적인 피드백을 제공합니다.

## 이슈 댓글 및 실행 링크

실행이 생성되면, Open SWE는 트리거된 이슈에 처리가 시작되었음을 확인하는 댓글을 자동으로 게시합니다. 이 댓글에는 다음이 포함됩니다:

- **상태 확인** - "🤖 Open SWE has been triggered for this issue. Processing..."
- **실행 링크** - Open SWE 웹 인터페이스에서 실행을 볼 수 있는 직접 URL
- **액세스 제한 안내** - 이슈 생성자만 실행에 액세스할 수 있음을 명시합니다
- **개발 메타데이터** - 디버깅을 위한 실행 ID 및 스레드 ID (접을 수 있는 섹션)

<Tip>
  실행 링크를 통해 실시간으로 진행 상황을 모니터링하고, 생성된 계획을 확인하고, 필요한 경우 에이전트와 상호 작용할 수 있습니다. 실행이 시작된 후에도 수동 모드와 자동 모드 간 전환이 가능합니다.
</Tip>

## 사용자 액세스 제한

Open SWE는 보안과 프라이버시를 보장하기 위해 엄격한 액세스 제어를 구현합니다:

### 이슈 생성자 액세스

- **이슈를 생성한 사용자만** 생성된 실행 URL에 액세스할 수 있습니다
- 이를 통해 권한이 없는 사용자가 다른 사람이 트리거한 실행을 보거나 수정하는 것을 방지합니다
- 액세스는 GitHub 인증 및 사용자 검증을 통해 시행됩니다

### 리포지토리 권한

- Open SWE는 GitHub의 리포지토리 권한을 존중합니다
- 사용자는 실행을 트리거하려면 리포지토리에 대한 적절한 액세스 권한이 있어야 합니다
- GitHub 앱 설치가 어떤 리포지토리에서 Open SWE를 사용할 수 있는지 결정합니다

<Note>
  실행에 대한 액세스를 팀원과 공유해야 하는 경우, 실행이 생성된 후 Open SWE 웹 인터페이스를 통해 공유할 수 있으며, 또는 리포지토리 액세스 권한이 있는 팀원이 자체 이슈를 생성하도록 할 수 있습니다.
</Note>

## Pull Request 통합

Open SWE가 코드 변경을 성공적으로 완료하면, 원본 이슈에 연결된 pull request를 자동으로 생성합니다:

### 자동 PR 생성

- **계획 실행 후 생성** - Programmer Graph가 작업을 완료하면 PR이 생성됩니다
- **트리거 이슈에 연결** - PR의 설명에 원본 이슈를 참조합니다
- **커밋 이력 보존** - 투명성을 위해 모든 중간 커밋이 유지됩니다

### 이슈 해결

- **자동 닫기** - 생성된 PR이 병합되면 GitHub가 자동으로 연결된 이슈를 닫습니다
- **명확한 감사 추적** - 이슈, 실행 및 PR 간의 연결이 완전한 추적 가능성을 제공합니다
- **상태 업데이트** - 이슈 댓글이 요청부터 완료까지의 진행 상황을 추적합니다

<Tip>
  자동 모드에서도 병합하기 전에 생성된 PR을 검토할 수 있습니다. 자동 승인 설정은 계획 승인에만 적용되고 PR 병합에는 적용되지 않으므로, 리포지토리에 어떤 코드가 들어갈지 최종 제어권을 갖습니다.
</Tip>

## 시작하기

웹훅으로 Open SWE 사용을 시작하려면:

1. **Open SWE가 설치되어 있는지 확인** - GitHub 앱으로 리포지토리에 설치되어 있어야 합니다
2. **상세한 이슈 생성** - 원하는 변경 사항을 설명하는 이슈를 작성합니다
3. **적절한 레이블 추가** - 수동 모드는 `open-swe`, 자동 모드는 `open-swe-auto`를 사용합니다
4. **이슈 댓글 모니터링** - 실행 링크와 상태 업데이트를 확인합니다
5. **PR 검토 및 병합** - Open SWE가 변경을 완료하면 PR을 검토하고 병합합니다

설정 지침은 [개발 환경 설정](/labs/swe/setup/development) 가이드를 참조하세요.
