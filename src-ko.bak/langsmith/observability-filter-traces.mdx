# 애플리케이션에서 추적 필터링

<Tip>
**권장 독서**


이 내용을 시작하기 전에, 여기에서 언급된 개념에 익숙해지기 위해 다음을 읽어보는 것이 도움이 될 수 있습니다:

- [추적에 대한 개념 가이드](/langsmith/observability-concepts)

</Tip>

추적 프로젝트는 상당한 양의 데이터를 포함할 수 있습니다. 필터는 이 데이터를 효과적으로 탐색하고 분석하는 데 사용되며, 다음을 가능하게 합니다:

- **집중된 조사**: 임시 분석을 위해 특정 실행으로 빠르게 좁히기
- **디버그 및 분석**: 오류, 실패한 실행 및 성능 병목 현상을 식별하고 검사하기

이 페이지는 추적 프로젝트에서 실행을 필터링하는 방법에 대한 일련의 가이드를 포함합니다. [API](https://api.smith.langchain.com/redoc#tag/run/operation/query_runs_api_v1_runs_query_post) 또는 [SDK](https://docs.smith.langchain.com/reference/python/client/langsmith.client.Client#langsmith.client.Client.list_runs)를 통해 분석을 위해 프로그래밍 방식으로 실행을 내보내는 경우, 자세한 정보는 [추적 내보내기 가이드](./export-traces)를 참조하세요.

## 필터 생성 및 적용

### 실행 속성으로 필터링

추적 프로젝트에서 실행을 필터링하는 두 가지 방법이 있습니다:

1. **필터**: 추적 프로젝트 페이지의 왼쪽 상단에 위치합니다. 여기에서 세부 필터 기준을 구성하고 관리합니다.

![Filtering](/langsmith/images/filter.png)

2. **필터 바로가기**: 추적 프로젝트 페이지의 오른쪽 사이드바에 위치합니다. 필터 바로가기 바는 프로젝트 실행에서 가장 자주 발생하는 속성을 기반으로 필터에 빠르게 액세스할 수 있습니다.

![Filter Shortcuts](/langsmith/images/filter-shortcuts.png)

<Info>
**기본 필터**

기본적으로 `IsTrace`가 `true` 필터가 적용됩니다. 이는 최상위 추적만 표시합니다. 이 필터를 제거하면 프로젝트의 중간 스팬을 포함한 모든 실행이 표시됩니다.
</Info>

### 시간 범위로 필터링

실행 속성으로 필터링하는 것 외에도 특정 시간 범위 내에서 실행을 필터링할 수 있습니다. 이 옵션은 추적 프로젝트 페이지의 왼쪽 상단에서 사용할 수 있습니다.

![Filtering on time](/langsmith/images/filter-time.png)

### 필터 연산자

사용 가능한 필터 연산자는 필터링하려는 속성의 데이터 유형에 따라 다릅니다. 다음은 일반적인 연산자에 대한 개요입니다:

- **is**: 필터 값에 대한 정확한 일치
- **is not**: 필터 값에 대한 부정 일치
- **contains**: 필터 값에 대한 부분 일치
- **does not contain**: 필터 값에 대한 부정 부분 일치
- **is one of**: 목록의 값 중 하나와 일치
- `>` / `<`: 숫자 필드에 사용 가능

## 특정 필터링 기술

### 중간 실행(스팬) 필터링

중간 실행(스팬)을 필터링하려면 먼저 기본 `IsTrace`가 `true` 필터를 제거해야 합니다. 예를 들어, 하위 실행에 대해 `run name`으로 필터링하거나 `run type`으로 필터링하려는 경우 이 작업을 수행합니다.

실행 메타데이터와 태그도 필터링에 강력합니다. 이는 파이프라인의 모든 부분에서 우수한 태깅에 의존합니다. 자세히 알아보려면 [이 가이드](./add-metadata-tags)를 확인하세요.

### 입력 및 출력 기반 필터링

실행의 입력 및 출력 내용을 기반으로 실행을 필터링할 수 있습니다.

입력 또는 출력을 필터링하려면 두 필드에서 키워드를 일치시킬 `Full-Text Search` 필터를 사용할 수 있습니다. 더 타겟팅된 검색을 위해, 해당 필드를 기반으로만 내용을 일치시킬 `Input` 또는 `Output` 필터를 사용할 수 있습니다.

공백으로 구분된 여러 용어를 포함하거나 여러 필터를 추가하여 여러 일치 항목을 지정할 수도 있습니다. 이는 제공된 모든 용어를 일치시키려고 시도합니다.

키워드 검색은 텍스트를 분할하고 검색 키워드에 대한 부분 일치를 찾는 방식으로 수행되므로 특정 순서로 수행되지 않습니다. 검색에서 일반적인 불용어를 제외합니다(nltk 불용어 목록과 몇 가지 다른 일반적인 json 키워드).

![Filtering](/langsmith/images/filter-full-text.png)

위의 필터를 기반으로 시스템은 입력 또는 출력에서 `python`과 `tensorflow`를 검색하고, 입력에서 `embedding`과 출력에서 `fine`과 `tune`을 검색합니다.

### 입력/출력 키-값 쌍 기반 필터링

전체 텍스트 검색 외에도 입력 및 출력의 특정 키-값 쌍을 기반으로 실행을 필터링할 수 있습니다. 이는 특히 구조화된 데이터를 다룰 때 더 정확한 필터링을 가능하게 합니다.

키-값 쌍을 기반으로 필터링하려면 필터 드롭다운에서 `Input Key` 또는 `Output Key` 필터를 선택합니다.

예를 들어, 다음 입력을 일치시키려면:

```json
{
  "input": "What is the capital of France?"
}
```

`Filters`, `Add Filter`를 선택하여 필터링 옵션을 표시합니다. 그런 다음 `Input Key`를 선택하고 키로 `input`을 입력하고 값으로 `What is the capital of France?`를 입력합니다.

![Filtering](/langsmith/images/search-kv-input.png)

점 표기법을 사용하여 중첩 키 이름을 선택하여 중첩 키를 일치시킬 수도 있습니다. 예를 들어, 출력에서 중첩 키를 일치시키려면:

```json
{
  "documents": [
    {
      "page_content": "The capital of France is Paris",
      "metadata": {},
      "type": "Document"
    }
  ]
}
```

`Output Key`를 선택하고 키로 `documents.page_content`를 입력하고 값으로 `The capital of France is Paris`를 입력합니다. 이렇게 하면 지정된 값과 함께 중첩 키 `documents.page_content`가 일치됩니다.

![Filtering](/langsmith/images/search-kv-output.png)

더 복잡한 쿼리를 생성하기 위해 여러 키-값 필터를 추가할 수 있습니다. 아래와 같이 일반적인 키 값 쌍을 기반으로 빠르게 필터링하기 위해 오른쪽의 `Filter Shortcuts`를 사용할 수도 있습니다:

![Filtering](/langsmith/images/search-kv-filter-shortcut.png)

### 예제: 도구 호출 필터링

특정 도구 호출을 포함하는 추적을 검색하는 것이 일반적입니다. 도구 호출은 일반적으로 LLM 실행의 출력에 표시됩니다. 도구 호출을 필터링하려면 `Output Key` 필터를 사용합니다.

이 예제는 도구 호출을 필터링하는 방법을 보여주지만, 동일한 논리를 출력의 모든 키-값 쌍을 필터링하는 데 적용할 수 있습니다.

이 경우, 필터링하려는 출력이 다음과 같다고 가정해 보겠습니다:

```json
{
  "generations": [
    [
      {
        "text": "",
        "type": "ChatGeneration",
        "message": {
          "lc": 1,
          "type": "constructor",
          "id": [],
          "kwargs": {
            "type": "ai",
            "id": "run-ca7f7531-f4de-4790-9c3e-960be7f8b109",
            "tool_calls": [
              {
                "name": "Plan",
                "args": {
                  "steps": [
                    "Research LangGraph's node configuration capabilities",
                    "Investigate how to add a Python code execution node",
                    "Find an example or create a sample implementation of a code execution node"
                  ]
                },
                "id": "toolu_01XexPzAVknT3gRmUB5PK5BP",
                "type": "tool_call"
              }
            ]
          }
        }
      }
    ]
  ],
  "llm_output": null,
  "run": null,
  "type": "LLMResult"
}
```

위의 예제에서 KV 검색은 각 중첩 JSON 경로를 검색하고 필터링하는 데 사용할 수 있는 키-값 쌍으로 매핑합니다.

LangSmith는 다음과 같은 검색 가능한 키 값 쌍 세트로 분해합니다:

| Key                                                | Value                                                                        |
| -------------------------------------------------- | ---------------------------------------------------------------------------- |
| `generations.type`                                 | `ChatGeneration`                                                             |
| `generations.message.type`                         | `constructor`                                                                |
| `generations.message.kwargs.type`                  | `ai`                                                                         |
| `generations.message.kwargs.id`                    | `run-ca7f7531-f4de-4790-9c3e-960be7f8b109`                                   |
| `generations.message.kwargs.tool_calls.name`       | `Plan`                                                                       |
| `generations.message.kwargs.tool_calls.args.steps` | `Research LangGraph's node configuration capabilities`                       |
| `generations.message.kwargs.tool_calls.args.steps` | `Investigate how to add a Python code execution node`                        |
| `generations.message.kwargs.tool_calls.args.steps` | `Find an example or create a sample implementation of a code execution node` |
| `generations.message.kwargs.tool_calls.id`         | `toolu_01XexPzAVknT3gRmUB5PK5BP`                                             |
| `generations.message.kwargs.tool_calls.type`       | `tool_call`                                                                  |
| `type`                                             | `LLMResult`                                                                  |

특정 도구 호출을 검색하려면 루트 실행 필터를 제거하면서 다음 Output Key 검색을 사용할 수 있습니다:

`generations.message.kwargs.tool_calls.name` = `Plan`

이렇게 하면 `tool_calls` 이름이 `Plan`인 루트 및 비루트 실행이 일치됩니다.

![Filtering](/langsmith/images/search-kv-tool.png)

### 키-값 쌍에 대한 부정 필터링

`Metadata`, `Input Key` 및 `Output Key` 필드에 다양한 유형의 부정 필터링을 적용하여 결과에서 특정 실행을 제외할 수 있습니다.

예를 들어, 메타데이터 키 `phone`이 `1234567890`과 같지 않은 모든 실행을 찾으려면, `Metadata` `Key` 연산자를 `is`로 설정하고 `Key` 필드를 `phone`으로 설정한 다음 `Value` 연산자를 `is not`으로 설정하고 `Value` 필드를 `1234567890`으로 설정합니다. 이렇게 하면 `1234567890`을 제외한 모든 값을 가진 메타데이터 키 `phone`이 있는 모든 실행이 일치됩니다.

![Filtering](/langsmith/images/negative-filtering-1.png)

특정 메타데이터 키가 없는 실행을 찾으려면 `Key` 연산자를 `is not`으로 설정합니다. 예를 들어, `Key` 연산자를 `is not`으로 설정하고 키를 `phone`으로 설정하면 메타데이터에 `phone` 필드가 없는 모든 실행이 일치됩니다.

![Filtering](/langsmith/images/negative-filtering-2.png)

특정 키도 특정 값도 없는 실행을 필터링할 수도 있습니다. 메타데이터에 키 `phone`도 값 `1234567890`을 가진 필드도 없는 실행을 찾으려면, `Key` 연산자를 `is not`으로 설정하고 키를 `phone`으로 설정하고, `Value` 연산자를 `is not`으로 설정하고 값을 `1234567890`으로 설정합니다.

![Filtering](/langsmith/images/negative-filtering-3.png)

마지막으로, 특정 키는 없지만 특정 값을 가진 실행을 필터링할 수도 있습니다. `phone` 키는 없지만 다른 키에 대해 값 `1234567890`이 있는 실행을 찾으려면, `Key` 연산자를 `is not`으로 설정하고 키를 `phone`으로 설정하고, `Value` 연산자를 `is`로 설정하고 값을 `1234567890`으로 설정합니다.

![Filtering](/langsmith/images/negative-filtering-4.png)

부분 문자열 일치를 수행하려면 `is not` 대신 `does not contain` 연산자를 사용할 수 있습니다.

## 필터 저장

필터를 저장하면 자주 사용하는 필터 구성을 저장하고 재사용할 수 있습니다. 저장된 필터는 추적 프로젝트에 특정합니다.

#### 필터 저장

필터 상자에서 필터를 구성한 후 **Save filter** 버튼을 클릭합니다. 이렇게 하면 필터의 이름과 설명을 지정하는 대화 상자가 나타납니다.

![Filtering](/langsmith/images/save-a-filter.png)

#### 저장된 필터 사용

필터를 저장하면 필터 바에서 빠른 필터로 사용할 수 있습니다. 저장된 필터가 3개 이상인 경우 두 개만 직접 표시되고 나머지는 "more" 메뉴를 통해 액세스할 수 있습니다. 저장된 필터 바의 설정 아이콘을 사용하여 기본 저장된 필터를 선택적으로 숨길 수 있습니다.

![Filtering](/langsmith/images/selecting-a-filter.png)

#### 저장된 필터 업데이트

필터가 선택된 상태에서 필터 매개변수를 변경합니다. 그런 다음 **Update filter** > **Update**를 클릭하여 필터를 업데이트합니다.

동일한 메뉴에서 **Update filter** > **Create new**를 클릭하여 새 저장된 필터를 생성할 수도 있습니다.

#### 저장된 필터 삭제

저장된 필터 바의 설정 아이콘을 클릭하고 휴지통 아이콘을 사용하여 필터를 삭제합니다.

## 필터 복사

구성된 필터를 복사하여 동료와 공유하거나 나중에 재사용하거나 [API](https://api.smith.langchain.com/redoc#tag/run/operation/query_runs_api_v1_runs_query_post) 또는 [SDK](https://docs.smith.langchain.com/reference/python/client/langsmith.client.Client#langsmith.client.Client.list_runs)에서 프로그래밍 방식으로 실행을 쿼리할 수 있습니다.

필터를 복사하려면 먼저 UI에서 필터를 생성할 수 있습니다. 거기에서 오른쪽 상단 모서리의 복사 버튼을 클릭할 수 있습니다. 트리 또는 추적 필터를 구성한 경우 이를 복사할 수도 있습니다.

이렇게 하면 LangSmith 쿼리 언어로 필터를 나타내는 문자열이 제공됩니다. 예: `and(eq(is_root, true), and(eq(feedback_key, "user_score"), eq(feedback_score, 1)))`. 쿼리 언어 구문에 대한 자세한 내용은 [이 참조](/langsmith/trace-query-syntax#filter-query-language)를 참조하세요.

![Copy Filter](/langsmith/images/copy-filter.png)

## 추적 뷰 내에서 실행 필터링

추적 뷰 내에서 직접 필터를 적용할 수도 있습니다. 이는 많은 수의 실행이 있는 추적을 선별하는 데 유용합니다. 기본 실행 테이블 뷰에서 사용할 수 있는 것과 동일한 필터를 여기에 적용할 수 있습니다.

기본적으로 필터와 일치하는 실행만 표시됩니다. 추적 트리의 더 넓은 컨텍스트 내에서 일치하는 실행을 보려면 뷰 옵션을 "Filtered Only"에서 "Show All" 또는 "Most relevant"로 전환합니다.

![Filtering within trace view](/langsmith/images/filter-runs-in-trace-view.png)

## LangSmith 쿼리 언어로 원시 쿼리 수동 지정

[이전에 구성된 필터를 복사](/langsmith/filter-traces-in-application#copy-the-filter)한 경우, 향후 세션에서 이 원시 쿼리를 수동으로 적용할 수 있습니다.

이렇게 하려면 필터 팝오버 하단의 **Advanced filters**를 클릭할 수 있습니다. 거기에서 텍스트 상자에 원시 쿼리를 붙여넣을 수 있습니다.

이렇게 하면 기존 쿼리에 해당 쿼리가 추가되고 덮어쓰지 않습니다.

## AI Query를 사용하여 쿼리 자동 생성(실험적)

정확한 쿼리를 지정하는 것이 어려울 수 있습니다! 더 쉽게 만들기 위해 `AI Query` 기능을 추가했습니다. 이를 통해 구성하려는 필터를 자연어로 입력하면 유효한 쿼리로 변환됩니다.

예: "All runs longer than 10 seconds"

## 고급 필터

### 루트의 속성에 대한 중간 실행(스팬) 필터링

일반적인 개념은 루트 실행에 일부 속성이 있는 추적의 일부인 중간 실행을 필터링하는 것입니다. 예를 들어, 루트 실행에 긍정적(또는 부정적) 피드백이 연결된 특정 유형의 중간 실행을 필터링하는 것입니다.

이렇게 하려면 먼저 위의 섹션에 따라 중간 실행에 대한 필터를 설정합니다. 그런 다음 다른 필터 규칙을 추가할 수 있습니다. 그런 다음 필터 맨 아래에 있는 `Advanced Filters` 링크를 클릭할 수 있습니다. 이렇게 하면 `Trace filters`를 추가할 수 있는 새 모달이 열립니다. 이러한 필터는 이미 필터링한 개별 실행의 모든 상위 실행의 추적에 적용됩니다.

![Filtering](/langsmith/images/trace-filter.png)

### 자식 실행에 일부 속성이 있는 실행(스팬) 필터링

이것은 위의 반대입니다. 특정 유형의 하위 실행이 있는 실행을 검색할 수 있습니다. 예를 들어, 이름이 `Foo`인 하위 실행이 있는 모든 추적을 검색하는 것일 수 있습니다. 이는 `Foo`가 항상 호출되지 않지만 호출되는 경우를 분석하려는 경우에 유용합니다.

이렇게 하려면 필터 맨 아래에 있는 `Advanced Filters` 링크를 클릭할 수 있습니다. 이렇게 하면 `Tree filters`를 추가할 수 있는 새 모달이 열립니다. 이렇게 하면 지정한 규칙이 이미 필터링한 개별 실행의 모든 자식 실행에 적용됩니다.

![Filtering](/langsmith/images/child-runs.png)
